# Validation Report — terrariabonker v0.21.0

**Date**: 2026-08-23
**Scope**: Spec 030 (build-keyed anchor ledger, multi-site patches, honest cheat status,
single-instance guard) and Spec 031 (window geometry).

## Summary

Three cheats — `mining`, `reach`, `max_minions` — had stopped applying. The diagnosis in the
error text was wrong, and the UI made it invisible.

`Player.ResetEffects` is JIT'd **twice** in the running process (one copy in the 16.5 MB JIT
arena, one in a 320 KB arena, byte-identical for 256 bytes; later differences are relative
call displacements). Their anchors therefore matched twice, and `_resolve` required a unique
hit. It raised *"anchor is not unique (game updated? re-derive AOBs with CE)"* — and Terraria
**had** just rebuilt (24825745 → 24893155), which made the wrong cause look confirmed. It was
not: 7 of 9 anchors still matched on the new build with identical field displacements.

Byte patches now apply to every identical copy, so the cheat works whichever copy executes.
Anchors carry a ledger of the builds they were confirmed on, failure reasons state only what
was observed, and the panel shows availability in the UI rather than repeating a log line.

## Phase 3 — Tests

- **192 passed** headless, up from 180 at the start of this work (155 before spec 030).
- `tests/test_build_ledger.py` (25): build keys, per-anchor verification, two identical
  copies resolving to both sites, the `unique` refusal, reasons that assert no unchecked
  cause, patch/revert across every site, `is_enabled` on any patched copy, migration of
  older single-address state, the `details()` contract, banner text, and the auto-restore
  summary lines.
- `tests/test_single_instance.py` (3): a second acquire is refused and names the holder, the
  lock is released when the holder lets go, and it lives outside the root-owned config dir.
- `tests/test_uistate.py` (6): size round trip, unset/corrupt/implausible values rejected, a
  failed write never blocking window close, and the path under `~/.cache`.
- Live on the running game: `patch status` showed all nine cheats resolving on
  `1.4.5.7+24893155`; `restore` returned `pending: []` for the first time, with `sites=2` on
  the three ResetEffects cheats; **maintainer confirmed mining, reach and the minion cap
  working in-game**, which is what put `1.4.5.7+24893155` into the ledger.
- Live: a second GUI launch started **no** second worker. A SIGKILLed holder left the lock
  file behind but the next launch acquired normally (`flock` is released by the kernel).
- Live: seeded window size 1100x1050 → KWin reported 1108x1086 (exactly, plus decoration).
- Live: `tools/kwin_rule.py` run install → install → remove against the real 13-rule
  `kwinrulesrc`; idempotent on re-run, and removal restored the original rule list with every
  other rule's content unchanged (verified by parsing both files section by section).

## Phase 4 — Code quality

- `ANCHORS` wraps the existing patterns rather than restating them, so the AOBs stay next to
  the comments explaining how each was derived and the ledger only adds provenance.
- `_resolve`/`_resolve_all` keep their call sites; the new `resolution()` is the single place
  that decides available/unavailable and why. `_resolve_all` stays deliberately uncached, as
  before, because a multi-site set can differ across re-JITs.
- Message text is a pure function (`client.build_banner`, `client.restore_summary`) so it is
  unit-tested rather than buried in widget code.
- flake8 clean at the project's ~100-col convention on all changed files; four pre-existing
  violations left untouched.

## Phase 5 — Security review

- No `eval`/`exec`, no shell strings; `tools/kwin_rule.py` spawns `kreadconfig6`/
  `kwriteconfig6`/D-Bus with explicit argv lists and fixed constants, and runs unprivileged.
- The single-instance lock lives in `XDG_RUNTIME_DIR` (mode 0700, per-user), not a shared
  world-writable path, so it cannot be pre-created or symlinked by another user.
- Window state is written to `~/.cache` with an atomic replace and bounds-checked on read.
- The installer writes to the user's own `kwinrulesrc` and the uninstaller removes it;
  verified lossless against a real file.
- No secrets, no network, no new dependencies. `pip-audit 2.10.0`: *No known vulnerabilities
  found*.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`, plus `tools/kwin_rule.py --remove` for the desktop rule. The
  anchor patterns themselves are unchanged, so reverting restores prior behaviour exactly.
- **State compatibility**: per-pid state gained a list-of-sites shape; the loader accepts the
  older single-address form, so an upgrade in place does not discard a live game's patches.
- **Degradation**: the ledger is provenance, not a gate — an anchor that resolves on an
  unverified build is still offered, marked. A hard gate would have disabled 7 working cheats
  after this rebuild.

## Known limitations

- **Why ResetEffects is JIT'd twice is not established.** Mono re-JIT, a second code-manager
  arena, or a domain event are all plausible. The fix does not depend on the cause, only on
  the copies being identical where they are patched.
- **A re-JIT after resolution** would leave the live copy unpatched until the state is
  re-resolved (per-pid state re-resolves on a new pid only).
- **Position memory is KDE-only.** Elsewhere the size is remembered and placement is left to
  the window manager.
- **A deliberately deleted lock file** (or a wiped `XDG_RUNTIME_DIR`) while a panel runs
  would let a second one start; inherent to path-based locking.

## Result

All gates pass. Approved for commit and tag `v0.21.0`.
