not in the repo and a hand-built metadata blob would test the parser against its

## Phase 4: Code quality

- Both commands are new; nothing existing was refactored.
- `cmd/winrecon` reuses `locate.ValidBlock` and `layout` constants instead of copying them,
  and reads the anchor table out of `internal/patch/anchors.go` with `go/parser`, so it
  tests exactly what the Linux build ships rather than a transcription.
- Duplication: `cmd/clrfields` and `cmd/winrecon` each open the process and walk regions
  with `VirtualQueryEx`. That is the code phase 1 moves into `internal/proc`'s Windows
  half; not extracted now, because phase 1 defines that package's shape.
- `make lint` (golangci-lint v2.12.2, pinned config): **0 issues** on Linux. Because
  `make lint` only sees Linux build tags, the Windows-only files were also linted with
  `GOOS=windows` over `./cmd/clrfields/... ./cmd/winrecon/...`: **0 issues**, after
  fixing 17 (3 unchecked `CloseHandle`, 1 unwrapped `OpenProcess` error, 1 capitalised
  error string, 1 parameter shadowing `min`, and 11 gosec G115 conversions — each
  suppressed per line with its reason, the repo's existing convention, since a 32-bit
  process's addresses and a field read as its bits are what these conversions are).
- Status: PASSED.

## Phase 5: Security review

- **Dependencies**: `govulncheck` v1.8.0 (`./...`, on the Linux tree with the new
  `go.mod`): no vulnerabilities found. `golang.org/x/sys` v0.48.0 was already in the
  module graph through fyne; only its `// indirect` marker changed.
- **Process access**: both commands open the game with `PROCESS_VM_READ |
  PROCESS_QUERY_INFORMATION` only. Neither has a write path; neither calls
  `WriteProcessMemory`, `VirtualAllocEx`, or `VirtualProtectEx`.
- **Input**: `clrfields` reads a PE file named by a flag (defaulting to the Steam path)
  with `debug/pe`; malformed input panics (see mutation 2) but cannot write anywhere.
  `winrecon -aob` parses a hex pattern; invalid tokens parse as zero, which only
  affects what is searched for.
- **Secrets, network, subprocesses**: none added. No credentials appear in the spec or
  docs. SSH to the maintainer's Linux machine was used during validation, by the
  maintainer's agent and key; nothing about it is in the repo.
- Status: PASSED.
