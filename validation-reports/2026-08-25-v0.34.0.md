# Validation Report — terrariabonker v0.34.0

**Date**: 2026-08-25
**Scope**: Passive potions (spec 041) — carry a favorited potion and its buff stays up.
Plus hellstone mining, obsidian in the sweep list, three latent bugs found while doing it,
and the panel reorganised into Player / Effects / Patches.

## Summary

The headline feature is passive potions, and it is the first cheat here that maintains a
value the game is already managing rather than adding something the game does not have.
That changes the failure mode: the risk is not "does nothing", it is "quietly degrades
something the player did by hand". A player who drinks Ironskin has eight minutes of it,
and a renewal loop writing its own short time over that would leave them with two seconds
the moment they dropped the stack — and they would blame the potion, not the trainer. The
guard against that is the centre of the design and was verified in the running game, not
only in tests.

Everything else in the release came out of chasing two reports from the maintainer.

## The part worth reading

**Hellstone: three wrong answers before the right one.** The report was that hellstone
poofed on every swing and stayed put while tin went in one hit. The diagnosis went wrong
three times in a row, and each wrong step is worth recording:

1. A probe reported *every* injection disabled while the game was demonstrably patched.
   That was believed and relayed to the maintainer. It was a bug in `_injection_enabled`,
   which returned `False` whenever both caches were cold without resolving anything — and
   cold is exactly the case that matters, a second process asking about a game it did not
   patch.
2. On that false reading, the advice was to restart the trainer. A restart does not rebuild
   a stub: it is written at *enable* time, and the extractor was already installed.
3. Then to toggle the cheat off and on. That rebuilds the stub — from the trainer's
   already-loaded copy of the old module. A Python process does not re-import an edited
   file.

What settled it was reading the stub bytes out of the arena and finding `6a 64` — `push
100` — still there. **Reading the game's memory should have been the first step, not the
fourth.** Every intermediate theory was reasoning about what the code ought to be doing.

The fix: pick power 100 → 250. A tile breaks on accumulated damage and the game credits
some tile types at a reduced rate, so 100 landed as 50 against a threshold of 100. 250 also
clears every pick-power constant `PickTile` actually contains (largest: 200). The immediate
no longer fits a byte, so the push widened to imm32 and the stub grew to 94 bytes — still
inside the arena slot, but the loop's backward `jnz` is a rel8 that would have broken
silently at 126 bytes, so it is guarded now.

**Anchors that could not find their own patched site.** Three injections spelled out the
very bytes they overwrite, so the anchor stopped matching the moment the cheat was applied.
A cold resolve then reported the cheat off *and could not find the site to take it back
off*. Fixed for `ore_extract` and `teleport`, both re-verified against the live game as
still resolving to exactly one site.

`pickup` is a documented exception and is the honest part of this: wildcarding its six
bytes takes the anchor from **1 live site to 124**. A wrong site is a corrupted game; a
wrong status is only a wrong status. So it keeps its literal patch site, its cold-cache
status stays unreliable, and an invariant test lists it as a known exception so it stays a
decision rather than an oversight.

**A screenshot found a bug.** Capturing the Compendium tab filtered to bosses showed the
label reading "6954 of 6954 entries" — the count was wired to the search box but never to
the kind dropdown. One line, one test.

## In-game verification

Tests do not prove a cheat works on the real thing. Verified live on 1.4.5.8+24893155:

- **Passive potions**: all eleven acceptance criteria in spec 041, including the one that
  matters most — a Night Owl potion drunk while the same potion sat favorited read 35578
  ticks (9.9 minutes) and four consecutive rounds each reported `kept` and left it there.
- **A favorited pet stays inert**, and non-vacuously: a favorited Slime Staff carrying buff
  64 with `consumable=0` sat in the bag throughout while ten potions beside it were taken,
  and buff 64 never entered the buff array.
- **Nothing consumed**: all six potion stacks read identically before and after.
- **Hellstone** breaks whole veins at the new pick power (maintainer-confirmed).
- **Obsidian** is swept (maintainer-confirmed).

## Security review (Phase 5)

- No `eval`/`exec`, no `subprocess`, no sockets, no new network calls in shipped code. The
  only `subprocess` in this work is a throwaway screenshot driver that was never committed.
- No hardcoded credentials. A GitGuardian alert against commit `bfe0422` was investigated
  and is a **false positive**: the match is Python's `pwd` module — the user *account*
  database (`/etc/passwd`), not a password. The line exists for security, to stop a cache
  file being chowned when `HOME` is root's under sudo.
- Dependencies unchanged since v0.33.0, so `pip-audit` was not re-run.
- Writes are still confined to the player's own process memory. Passive potions write two
  ints per buff slot and nothing else.

## Release safety

- **Rollback**: `git revert` or check out the previous tag. Passive potions need no undo —
  stop renewing and the buffs expire on their own within seconds. Nothing is patched, so
  there are no displaced bytes to restore and no world or save state is written.
- The one destructive cheat in the tool (the ore extractor) is unchanged in that respect;
  the pick-power change makes it break tiles it previously failed to break, which is the
  intended behaviour and is still irreversible by nature.
- The GUI reorganisation is presentation only.

## Known gaps

Recorded rather than smoothed over:

- **Hardmode ores on the new pick power are inference, not a test.** 250 clears every
  constant found in `PickTile`, but no hardmode vein has been mined with it. The maintainer
  is checking separately.
- **`pickup`'s cold-cache status stays unreliable** (above). While that cheat is on, a
  trainer that did not install it cannot find the site to disable it.
- The projectile research in `docs/item-fields.md` leaves two questions open: which of two
  boolean fields is `tileCollide`, and what the field mirroring `penetrate` is for. Nothing
  writes there, and nothing should until both are answered.
