# Validation Report — terrariabonker v0.42.0

**Date**: 2026-09-18
**Scope**: Spec 051 — the rest of the tool in Go. The Python implementation is deleted,
the CLI is a Go binary, the tools that were scripts are Go commands, and CI builds and
releases on a tag.

## Summary

104 commits since v0.41.1. 42,108 lines added and 24,591 removed across 302 files, which
is mostly one implementation replacing another: 25,023 lines of Go and 14,412 lines of Go
tests where there were 9,686 lines of Python and 10,049 lines of Python tests.

**653 Go tests pass, with no interpreter and no skips.** `make lint` is clean at the
pinned golangci-lint v2.12.2. `govulncheck ./...` reports no vulnerabilities.

Nothing was deleted on the strength of a passing test. Every module was run against the
Python it replaced, over the same bytes, until the two agreed — and where the answer is
about the running game rather than about a fixture, against the running game.

## What the differential runs established

| | checked | result |
| --- | --- | --- |
| Sprites | every `Item_*.xnb` in the install | 14,015 byte-identical |
| Icons | the built PNG cache | 6,901 pixel-identical |
| Anchors | the live game, both implementations | 17 of 17, same addresses |
| Player scan | the live game, 1,466 regions | same two copies, same names |
| Local player | the live game, 1,492 executable regions | same anchor, same address |
| Patches | applied to a running game and watched | 14 of 15 |

`pylons` is the one patch not applied live: it patches a method the game does not compile
until a pylon is placed.

The icon comparison is on pixels, not file bytes, and that is not a weakening. Two PNG
encoders disagree about filter choice and chunk order while agreeing about every pixel;
comparing the file would have compared the encoders.

## Tests

**653 tests, down from 738.** That is a deliberate reduction, decided by the maintainer
partway through step 9 and recorded in spec 051 under AC4.

Roughly 150 of the remaining Python tests were coupled to Python — they drove the CLI
through an interpreter, asserted on a module's own source text, or pinned the shape of a
data structure that has no counterpart in Go. Translating them was costing more than they
were worth. The rest of the suite came over as behaviour.

What replaced the translation, where a test's expected value would otherwise have been a
second copy of the thing under test:

- **Digests.** `internal/patch/toggle_test.go` freezes a `sha256` of the whole planted
  buffer for each of the 15 patches, enabled and disabled, plus the anchor table and the
  catalog. A transcribed copy gets edited to match when it disagrees. A digest does not.
- **Literals with provenance.** `cmd/prefixstats` reproduces `data/prefix_stats.json`
  byte for byte from a captured IL dump, and a second test reads two of its rows off the
  IL by hand, at the addresses it names — because a tool compared against a file it wrote
  itself proves only that it agrees with itself.

Two automated dead-code sweeps were tried during the lint cleanup and **both deleted
working code**, the second silently: a fixture's `Read` and `Write` are reached through an
interface, so `unused` calls them dead, and removing one left a planted game that mined
nothing and a test that still passed. Both sweeps were reverted, the `unused` linter is
now off for test files with that reason written next to it, and the remainder was done by
hand against `go test`, not `go vet`.

## Security review (Phase 5)

- `govulncheck@v1.8.0` against the Go 1.27.1 toolchain: **no vulnerabilities found**.
  Pinning the linter's Go 1.26.0 toolchain reports 18 standard-library advisories fixed in
  1.26.1; the release builds on a current toolchain, and CI asks setup-go for the latest.
- **The privilege boundary did not move.** The GUI runs unprivileged and reaches memory
  only by running the CLI under sudo, through a `serve` worker or a one-shot run. No
  in-process root memory access was added.
- `serve` keeps an explicit allowlist of the operations it will run; it does not take an
  arbitrary argv from the window.
- Every subprocess is spawned with an explicit argv and no shell. The one `gosec` G204
  suppression is `proc.Elevate`, which re-runs this same binary under a `sudo` resolved
  through PATH.
- No secrets, no network calls, no game assets shipped: icons are decoded from the user's
  own install into a local cache.
- Dependencies: cobra (the CLI) and fynedesygn (the window), both already in use in the
  sibling projects, plus the Fyne pin fynedesygn carries.

## Release safety

- **Rollback** is a revert. The previous release's binaries were installed from this same
  checkout, so `git checkout v0.41.1 && ./install.sh` puts the Python back — until this
  tag, after which it is the last commit that has it.
- The on-disk state this tool keeps (`~/.config/terrariabonker/patches.json`,
  `profile.json`, the sprite cache) is read and written in the same formats; a downgrade
  reads what this version wrote.
- Nothing about the game's memory layout changed in this release. The offsets are the
  values that were diffed against the Python's, not re-derived.

## Known gaps

- **The screenshots in `assets/` are the Qt window's successor from spec 050 and have not
  been recaptured for this release.** They still match what the panel shows; they need the
  game and the panel running to refresh, which is a maintainer step.
- **`pylons` has not been applied to a live game** for the reason above.
- **The crash question from v0.41.1 is still open.** Two untraced crashes during
  structural operations were recorded there; nothing in this release addressed them, and
  the end-to-end run with every patch applied, watched through the window, has not been
  done yet.
- `terrariabonker version` needs a running game, so CI's smoke test checks that the
  binaries start and report the version they were stamped with, and nothing further.
