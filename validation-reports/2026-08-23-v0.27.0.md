# Validation Report — terrariabonker v0.27.0

**Date**: 2026-08-23
**Scope**: Spec 035 — item compendium, **Phase 3 of 3** (NPC artwork), plus the UI
consistency and progress work that came out of reviewing it. Spec 035 is now COMPLETE.

## Summary

NPC rows carry sprites: 697 sheets decoded alongside the 6,193 item sprites in ~24 s. Sheets
are cropped to a single frame with the game's own `Main.npcFrameCount` rather than a shape
heuristic; the handful laid out as grids are cropped to their top-left cell; and the slimes
the game tints at draw time are painted with the colour it would use.

## The part worth reading

**The item de-animator could not be reused.** It infers a strip from `height >= 2*width` plus
evenly spaced content blocks — right for tall item strips, wrong for wide NPCs. A two-frame
Blue Slime sheet is 32x52 and comes back whole; a one-frame Moon Lord is 573x804.

The exact answer is `Main.npcFrameCount`, an `int[697]` at Main-static **+0x0C34**, found by
scanning Main's statics for an array whose values divide the sheet heights, and confirmed
against every sheet measured: Guide 1456/26, Bunny 280/7, Eye of Cthulhu 996/6, Blue Slime
52/2, Moon Lord 804/1.

**Three things the first attempt got wrong, each caught by the maintainer looking at it.**

1. *Bosses still looked like sheets.* Requiring the frame count to divide the height exactly
   left Duke Fishron (1298 over 8) and Skeletron Prime (940 over 6) whole over two to four
   rows of padding. The division is now floored.
2. *Some sheets are grids, not strips.* `npcFrameCount` counts frames, not rows. A pass that
   crops to the top-left cell handles them, and is stopped from slicing single sprites by
   requiring the blocks to be **evenly sized** — measured over all 697 sheets it changes 19
   and leaves 678 untouched, which is the number that made it safe to ship.
3. *Queen Slime was half a slime.* Its 16 frames are 2 columns of 8, so dividing the height by
   16 cut a cell in half. Columns are counted first and the height divided by the rows that
   implies. Re-measured across all 697: exactly one sheet changes.

**The colour report turned out to be a real bug, but not the reported one.** Chasing Queen
Slime's colour showed Blue Slime's sheet is **neutral grey (117,117,117)** — the game tints
slimes when it draws them. `NPC.color` sits at **+0x1A8** and holds exactly `(0, 80, 255, 100)`
for Blue Slime, vanilla's own `Color(0, 80, 255, 100)`; it is non-zero on 11 templates. Those
11 now render in their proper colours instead of grey.

The tint is per **netID** while the sheet is per **type** — every coloured slime shares one
neutral sheet — so tinted variants get their own cached icon, and the tint crosses the
privilege boundary with the frame counts.

Queen Slime itself carries no tint (`(0,0,0,0)`), so the pink lives in its draw code rather
than in readable data. Reproducing it would mean inventing a colour. Reviewed with the
maintainer and **shelved**, recorded in the spec so the dead end is not re-derived.

## The progress work

The maintainer reported not seeing the progress bar, and that the main part of the wait was
not covered. Measured, they were right on both counts:

| stage | time | covered before |
| --- | --- | --- |
| privileged catalog read | 2.4 s (longer cold) | no |
| building 6,954 compendium rows | 1.3 s, UI frozen | no |
| recipe grid build | seconds, UI frozen | no |
| sprite extraction | 0 s when cached | yes — so it never appeared |

The row build was the worse half: nearly 7,000 rows of seven cells, each with an icon and a
tooltip, built in one go. A frozen window cannot paint a progress bar, so instrumenting it
without slicing it would have achieved nothing. Both big grids now build in slices of 500 with
the event loop pumped between them — which also made the compendium fill *faster*, 1.29 s to
0.86 s — and all four operations report through one bar under the tabs, visible whichever tab
started the work.

**UI consistency**: the Compendium gained **Re-scan from game**, matching the Recipes tab's
**Re-extract from game**. Both catalogs are read from the game once and cached per build, so
both needed the same escape hatch after a game update. It is backed by a new
`compendium --refresh`, verified end-to-end by watching the cache file be rewritten.

## Phase 3 — Tests

- **313 passed** headless, up from 290 at v0.26.0.
- `tests/test_npc_sprites.py` (15): strips cropped to one frame; a wide two-frame sheet cropped
  where the item rule provably would not; a single-frame sheet left alone; padding tolerated;
  an absurd implied frame ignored; NPC and item cache paths cannot collide; draw data round
  trips and a missing file is not an error; a stale scope and an NPC-less cache both
  re-extract; extraction with no counts writes no NPC icon at all; grid sheets cropped to the
  top-left cell; the tint is added rather than multiplied (a multiply is too dark to read at
  40px); a tinted variant has its own path; **and a single sprite with a detached piece is
  left untouched**, which is the dangerous direction.
- `tests/test_compendium_tab.py` (15): plus an NPC variant taking its sprite from its base
  type and the netID driving only the tint; progress reported from fetch through to the last
  row; a failed fetch taking the bar down; and re-scan clearing rows, kinds and asking for a
  fresh read.
- `tests/test_gui_construct.py` (4): plus extraction reporting through the progress bar.
- **Mutation checks**, since each of these tests exists to catch a specific bug: restoring the
  whole-run scan rule fails the Hornet test; removing the boss gate fails 4; asking for the
  sprite by netID fails the variant test; removing the progress calls fails the progress
  tests; never showing the bar fails the extraction test.
- Every crop change was measured against all 697 sheets before shipping, not sampled.

## Phase 4 — Code quality

- `_first_frame` and `_first_grid_cell` are separate, and each documents the failure it exists
  to prevent. The evenness constant and the minimum frame height are named rather than inline.
- The chunk size for both grids is a named constant with the reason attached.
- `busy()` is one method on the window rather than a per-tab bar, because the work it covers is
  started by one tab and blocks all of them.
- flake8 clean at the project's ~100-col convention on all changed code; the same three
  pre-existing hits remain in untouched lines.

## Phase 5 — Security review

- No `eval`/`exec`, no `pickle`, no shell, no network, no new dependencies. `pip-audit 2.10.0`:
  *No known vulnerabilities found*.
- Phase 3 adds **no memory writes** — it only reads two more things (`Main.npcFrameCount`, and
  `NPC.color` from the template block already being read) and writes PNGs into the user's own
  cache. No patches, no code caves, nothing for the build ledger.
- The frame counts and tints are written through `proc.give_back_to_user`, which since v0.25.0
  only hands over paths inside the invoking user's home.
- `compendium --refresh` widens no privilege: it is the same allowlisted op, and the flag only
  decides whether a cache file is read before scanning.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Everything added here is read-only against the game.
- **Cache scope bumped to `all-v4`**, so existing sprite caches re-extract rather than serving
  wrongly cropped NPC icons; an extraction that runs before the frame counts are published
  skips the NPC sheets and reports itself incomplete rather than caching whole strips.
- **Disposable state**: every cache regenerates from the game.

## Known limitations

- **Queen Slime's colour is not reproduced** and the attempt is shelved with the maintainer's
  agreement (see above).
- **A handful of sheets are not vertical strips or even grids** — the Wyvern segments, the four
  Pillars, the Flying Dutchman, Foxparks — and are deliberately left whole. At 40px an
  oversized source is cosmetic rather than wrong.
- **`processEvents()` between grid slices** is re-entrant by nature. The load guards already in
  place stop a second load starting; the worst case is a click landing on a half-built model,
  which opens a dialog on a real row.
- **Spec 034** still has its one open criterion (`SmartCursorLookup` before it is JIT-compiled).

## Result

Gates pass. Approved for commit and tag `v0.27.0`. **Spec 035 is COMPLETE** — all three phases
implemented and validated in-game.
