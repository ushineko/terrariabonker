# Validation Report — terrariabonker v0.33.0

**Date**: 2026-08-25
**Scope**: Stop borrowing code padding. Every cheat's stub now lives at an address we
choose, inside memory we allocated. Prompted by two crashes in one morning, both caused by
searching for space.

## Summary

`_find_cave` looked for runs of cold bytes (0xCC or zero) in executable memory and borrowed
them. It is a heuristic, and it cannot answer the one question that matters: *is this space
actually free?* Disabling a stub scrubs its cave to 0xCC, which is precisely the pattern the
scan prefers — so a used cave becomes bait, and our own freshly-allocated arena was the most
attractive cave in the process.

Placement is now by index. Each injection site has a fixed slot in the arena, decided by
which injection it is. Two stubs cannot overlap because nothing chooses between them.

## The part worth reading

**Two crashes, one cause.** The morning began looking like a Terraria update and was
neither.

The first was a missing `+ inj.inject_off` in the arena bootstrap, shipped in v0.32.0 and
released in v0.32.1 — covered by that report. The second is this one:

```
ore_extract      cave 0x68000000  len 96   -> [0x68000000, 0x68000060)
inventory_accs   cave 0x68000002  len 57   -> [0x68000002, 0x6800003B)
```

One stub written inside another. Whatever ran was the splice: `ebp` came back as `1`, the
next `mov eax,[ebp+8]` read address 9, and mono then crashed while unwinding the
NullReferenceException it had raised. The fatal fault was in `libmono+0xa2908`, four frames
away from anything of ours — the sort of evidence that is useless without the first
exception, which the Proton log had kept.

The setup was our own: enabling the extractor wrote its stub at the arena base; disabling it
scrubbed 96 bytes to 0xCC; the next cheat enabled found that "cave" and took it.

## What changed

- **`_exec_regions` excludes the arena.** Memory we placed something in is not padding.
- **`_find_cave` avoids every cave in our own state**, not just those claimed during the
  current call — a stub from an earlier enable was invisible to it.
- **`slot_for(name, site)`** gives each site a fixed address: `ARENA_STUBS_OFF + index *
  ARENA_SLOT`, indexed by sorted injection name. 72 slots, no overlap possible, same
  address every time, so enable/disable/re-enable lands on the same bytes.
- **The arena grows to 64KB**, VirtualAlloc's reservation granularity — a smaller request
  reserved that much anyway.
- **All nine injections moved in.** `_find_cave` retains one caller: the ~36-byte
  springboard that asks the game to allocate, which necessarily runs before the arena
  exists. One transient borrow instead of twelve long-lived ones.
- **`_check_site`** refuses to write a jump over bytes that are not what would be put back
  (added in v0.32.1, kept here because it guards the same class from the other side).

## The constraint this created, and its fix

Allocating means asking the game to call `VirtualAlloc`, which needs frames. Terraria pauses
in single-player when unfocused — and enabling a cheat from the panel *requires* clicking
the panel. Allocation would have failed exactly when it was needed.

So it does not happen on the toggle. `ensure_arena` is called from the status poll the panel
already runs every couple of seconds, which is the one moment the game is reliably focused
and simulating. By the time anyone toggles a cheat the arena exists, and `enable()` never
touches the bootstrap. Measured: a disable+enable cycle with a warm arena takes 0.00s.

It never raises and never blocks — if frames are not advancing there is nothing to do yet
and the next poll tries again.

## Phase 3 — Tests

- **401 passed** headless, up from 397.
- Slot placement: deterministic, non-overlapping across every injection and site, clear of
  the extractor's queue and the arena stamp, and refusing an unknown injection or a site
  past the reservation.
- The arena is excluded from cave scanning; a cave is never handed out twice.
- `ensure_arena` does nothing on a paused game, does not re-allocate a warm arena, and
  swallows a failed allocation.
- Verified live with all fourteen cheats applied: every stub at its assigned slot, game
  healthy, frames advancing.

**A test that passed for the wrong reason.** The first arena-exclusion test passed with the
guard removed, because the shared fixture replaces `_exec_regions` — so it never ran the
method it was checking. Rewritten to drive the real one against a fake maps file, and the
mutation is caught.

## Phase 4 — Code quality

- Liveness is sampled from Main's statics, not the player: a player standing still changes
  nothing, which produced a wrong "the game is paused" diagnosis earlier in the day.
- flake8 clean on changed files; the same pre-existing hits remain in untouched lines.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no dependency changes. `pip-audit` against
  `requirements.txt`: *No known vulnerabilities found*.
- This release removes a memory-safety hazard rather than adding one: stubs can no longer
  be placed on top of each other, and a jump is no longer written over bytes we would not
  restore.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Stubs are session-only; disabling restores the displaced bytes
  and a restart clears everything.
- The arena is 64KB of RWX per game process, kept rather than freed on disable — freeing
  memory another thread might still be executing is the riskier operation.

## Known limitations

- **The arena must be allocated while the game runs.** Warming covers the normal path; a
  first enable on a game that has never been focused will still fail, with a message saying
  so.
- **The bootstrap still borrows.** One ~36-byte springboard, transient, scrubbed after use —
  but it is the same technique, and it is the one place that cannot use the arena.
- **`ARENA_MAX_SITES` is 8.** An anchor matching more than eight structural twins would
  raise rather than silently overlap. The largest today is four.

## Result

Gates pass. Approved for commit and tag `v0.33.0`.
