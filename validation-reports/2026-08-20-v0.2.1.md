# Validation Report — terrariabonker v0.2.1

**Date**: 2026-08-20
**Scope**: Authoritative item-name map for 1.4.5.7, extracted from `Terraria.exe`,
plus the `tools/extract_item_names` dotnet tool that produces it.

## Summary

The bundled item-name map was 1.4.4.1 (5,453 items), leaving 1.4.5-new items (e.g.
id 5544) unnamed — and no public 1.4.5 `ItemID.cs` exists yet. This release extracts
the complete map straight from the game's own assembly: `ItemID` constant fields
(internal-name → id) joined with the embedded `en-US.Items.json` localization
resource (internal-name → display name). Result: **6,195 items** for the exact
1.4.5.7 build. A reusable dotnet tool is bundled so the map regenerates after future
patches.

## Phase 3 — Tests

- **41 passed** headless (unchanged suite; name map is data).
- Tool verified: `dotnet run` against the installed `Terraria.exe` reproduces the
  6,195-item map (`5544 → Cloud Platform`, `5400 → The Dirtiest Block`, Zenith 4956,
  Treasure Magnet 5010).
- `names.count()` = 6195; previously-unnamed ids now resolve.

## Phase 4 — Code quality

- `ruff check` → passed (no Python changed beyond the `names.py` docstring).
- Tool is dependency-free (`System.Reflection.Metadata` + `System.Text.Json` from
  the shared framework); build output (`bin/`, `obj/`) git-ignored.

## Phase 5 — Security review

- **Data provenance**: `items.json` is derived solely from the user's own installed
  `Terraria.exe` (localization strings + public ItemID constants). No network fetch,
  no third-party data. No secrets.
- The tool only *reads* the exe (opens for read, parses metadata); it does not
  execute or modify the game assembly.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`; the previous 5,452-item map is in history. Data-only
  plus an isolated tool; no runtime code path changed.
- **Additive**: no API/behaviour change; more items simply resolve to names.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.2.1`.
