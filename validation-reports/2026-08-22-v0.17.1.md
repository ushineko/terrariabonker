# Validation Report — terrariabonker v0.17.1

**Date**: 2026-08-22
**Scope**: Spec 025 — graceful behavior when passwordless sudo is missing.

## Summary

Without passwordless sudo the GUI's memory actions used to fail silently (a `QProcess` has
no TTY to answer a sudo prompt). Now the GUI: checks `sudo -n true` at startup and shows a
persistent, actionable warning banner (pointing at the README's NOPASSWD instructions) when
it fails; runs its memory spawns with non-interactive `sudo -n` so they fail fast with a
reason instead of hanging/silent; and keeps the unprivileged features (recipe browser, item
icons) working. It does not refuse to start — the CLI also still works with an interactive
password prompt.

## Phase 3 — Tests

- **115 passed** headless (no test changes needed; the change is GUI startup behavior).
- Offscreen render with `_passwordless_sudo` stubbed to False showed the warning banner and
  a usable window (tabs present); with sudo available the banner stays hidden.

## Phase 4 — Code quality

- flake8 clean. Small, localized change: `-n` added to `_cli_args`, a `_passwordless_sudo`
  helper, `_check_sudo` + a banner label. No new dependencies (`subprocess` is stdlib).

## Phase 5 — Security review

- No new dependencies, no network. The change only detects/announces sudo availability and
  makes existing sudo calls non-interactive. The README's NOPASSWD example is tightly scoped
  to the trainer's entry point (not a blanket interpreter rule). No secrets; no `eval`/
  `exec`/shell-string injection (spawns use explicit argv lists).

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. GUI-only; no memory writes, no persisted state, no new deps.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.17.1`.
