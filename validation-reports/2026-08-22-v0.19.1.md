# Validation Report — terrariabonker v0.19.1

**Date**: 2026-08-22
**Scope**: Relocatable installer fix, first release after the repo was split out of the
`ag-scripts` monorepo into its own repository (`github.com:ushineko/terrariabonker.git`).

## Summary

`terrariabonker.desktop` shipped a hardcoded absolute path to the old monorepo location
(`/home/nverenin/git/ag-scripts/terrariabonker/...`) in its `Exec` and `Icon` lines, and
`install.sh` copied it verbatim. After the repo move that path no longer exists, so the
installed desktop entry pointed at a deleted location; the path was also meaningless for any
other clone location. The desktop file is now a template with `__SCRIPT__` / `__ICON__`
tokens, and `install.sh` resolves them to the actual install directory (`$APP_DIR`, derived
from the script's own path) at install time. The CLI symlink was already self-locating and is
unchanged in behaviour. Version bumped 0.19.0 → 0.19.1.

## Phase 3 — Tests

- **119 passed** headless (`pytest`), unchanged from v0.19.0. The change is install-tooling
  only and touches no importable code path.
- Manual install verification from the new location:
  - `~/.local/bin/terrariabonker` → `/home/nverenin/git/terrariabonker/terrariabonker.py`.
  - Installed `terrariabonker.desktop` `Exec`/`Icon` resolve to the new repo paths, both of
    which exist.
  - `terrariabonker --help` runs through the symlink (exit 0).

## Phase 4 — Code quality

- `install.sh` change is minimal: add `APP_DIR`/`ICON_PATH`, replace the verbatim `cp` with a
  two-token `sed` that writes the resolved entry. No duplication introduced; the desktop file
  is the single source of the entry's static fields.
- No Python changed; flake8 not applicable to the modified files (`install.sh`, `.desktop`).

## Phase 5 — Security review

- No new dependencies, no network. `sed` substitutes only two build-local, non-user-supplied
  path variables into a file under the user's own `~/.local/share/applications`. No secrets;
  no `eval`/`exec`; no privilege change (install runs unprivileged).

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Re-running an older `install.sh` (or `uninstall.sh` + reinstall)
  restores the previous state; the uninstaller removes the entry by name, unaffected by the
  path change.

## Result

All gates pass. Approved for commit and tag `v0.19.1`.
