# Validation Report — terrariabonker v0.11.0

**Date**: 2026-08-21
**Scope**: Spec 013 — spawn-rate cheat (`GetSpawnRate` code-cave injection).

## Summary

Adds `spawn_rate`: forces the outputs of `Spawner.GetSpawnRate(out spawnRate, out
maxSpawns)` — a low spawnRate and a tunable maxSpawns (active-enemy cap; 0 = peaceful).
Same `out esi / out edi`-at-the-epilogue shape as `GetRanges`, so it reuses the code-cave
injection. Ported from the FearLess ReGrind table and re-derived for 1.4.5.7.

## Phase 3 — Tests

- **84 passed** headless (1 new: injection round-trip — stub `mov [esi],6; mov [edi],40`
  + the overwrite, byte-perfect restore). Status set widened to include `spawn_rate`.
  Parity test covers the argv.
- **Live** (game pid 1632717): the anchor resolved uniquely to `GetSpawnRate`
  (0x1c6b3bf0); the stub forced spawnRate=6, maxSpawns=40. In-game the enemy count
  swarmed well past vanilla (surface cap ~5–8) — confirmed. Disable restored the exact
  original bytes (`8d 65 f4 5e 5f`).

## Phase 4 — Code quality

- `ruff check` → passed. Reuses `Injection`/`make_body` (`_force_spawn`); anchor is the
  method prologue + fldz/first-store with ASLR immediates wildcarded (unique, verified).
  Default maxSpawns 15 (noticeable, not overwhelming); 0–200 range.

## Phase 5 — Security review

- No new inputs beyond a range-bounded int, no network, no new dependencies. The
  injection edits the game's own code over the existing `/proc` path; a wrong anchor is
  guarded by the unique pattern + verified restore. Secrets: none.

## Phase 5.5 — Release safety

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.11.0`.
