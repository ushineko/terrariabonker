# Validation Report — terrariabonker v0.16.0

**Date**: 2026-08-22
**Scope**: Spec 023 — named, damage-class-filtered item modifiers, with the modifier in the
item name and a colour-coded quality dot in the inventory.

## Summary

The item editor's prefix field is now a named dropdown filtered to the item's damage class
(melee/ranged/magic/summon weapons and accessories each offer only their own modifiers),
instead of a raw integer that offered every value. A modified item shows its modifier in the
name ("Fabled Slime Staff") and a green/red/gray corner dot in the inventory grid. Modifier
names come from `data/prefixes.json` (extracted from Terraria.exe via a new `--prefixes`
mode); `prefixes.py` holds the class pools + good/bad quality; the item's class flags are
read from memory (offsets from CE recon) and flow to the GUI via the inventory JSON.

## Phase 3 — Tests

- **114 passed** headless (7 new). `test_prefixes.py`: name lookup, quality, and
  applicability (summon → summon+universal, excludes melee-size and accessory; accessory is
  accessory-only; melee has size+universal, not magic). `test_invgrid.py` updated for the
  named modifier tooltip line.
- **Live**: CE recon (`ce/poc_itemcat.lua`) found the class-flag offsets; validated on the
  player's items (Slime Staff/Slime Whip `summon=1`, pickaxe/axe `melee=1`). Offscreen
  renders confirmed the editor dropdown ("Fabled (85)" selected, melee-size and accessory
  excluded, summon included) and the inventory dots (Fabled=green, Broken=red, Warding=green,
  unmodified=none) plus the "Fabled Slime Staff" tooltip.

## Phase 4 — Code quality

- flake8 clean on changed files. `prefixes.py` is a small pure module (names + pools +
  quality); the class flags thread through `inventory.Slot.flags` → `service.ItemSlot.flags`
  → JSON with no new plumbing. The editor's spinbox → combo is localized.

## Phase 5 — Security review

- No new runtime dependencies. Modifier names are extracted from the user's own
  `Terraria.exe` (assembly metadata, disk read) by the existing dotnet tool; class flags are
  read over the same sudo `/proc` path already used for inventory. `data/prefixes.json` is
  committed (game-derived functional data, like `items.json`). No secrets; no `eval`/`exec`/
  shell. The write path (`set-item --prefix N`) is unchanged (still a bounded int).

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Data + GUI/read changes only; no new write behaviour. A
  mis-categorised modifier only mislabels/misfilters (the current value stays selectable),
  never corrupts an item.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.16.0`.
