Before this work, on Windows: 13 packages did not compile and 2 tests failed.

**Test isolation.** The first Windows run leaked: tests isolated by `HOME`, which Windows
ignores, so they wrote into the real `%APPDATA%\terrariabonker` and
`%LOCALAPPDATA%\terrariabonker`. Neither directory existed before the run (created
16:49 during it); both were deleted. After the fix the suite was re-run with `APPDATA`,
`LOCALAPPDATA`, `USERPROFILE` and `HOME` pointed at a trap directory: nothing of this
program's landed there (only Go's own build cache and telemetry). The real directories
were checked empty after every run since. On Linux, `~/.config/terrariabonker` was
last written 2026-09-19, so the suite did not touch it.

**New tests**, all headless:

- `filelock`: a second holder is refused until the first releases; closing the file
  drops the lock; the contents stay readable while locked.
- `paths`: the directories are the literal old Linux spellings with `XDG_*` set (proving
  they are ignored), and `%APPDATA%`/`%LOCALAPPDATA%` on Windows.
- `proc.Alive`: true for this process, false for an exited child (this test binary run
  with no tests selected).
- Windows `proc.Mem` against a real process — its own: a page allocated below 4 GB (the
  64-bit test binary's heap is above it), planted and observed through direct Win32
  calls independent of `Mem`; read, write, a short read past a region's end, and the
  three region lists.
