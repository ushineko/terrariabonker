# Validation Report — terrariabonker v0.7.0

**Date**: 2026-08-21
**Scope**: Spec 008 — edit item prefix (modifier tier) and defense. Two new offsets.

## Summary

The item editor can now set `Item.defense` (0xD4) and `Item.prefix` (0x15C),
completing "edit an accessory like a weapon/tool". Defense was found by an armor tier
ladder (template diff); prefix — not template-diffable, since every ContentSamples
template has prefix 0 — was read from mono metadata with Cheat Engine
(`ce/poc_item_fields.lua`), which also cross-checked every existing offset.

## Phase 3 — Tests

- **73 passed** headless (1 new: tooltip shows defense/prefix). Parity test covers
  `set-item --defense/--prefix` argv.
- **Live** (game pid 1632717): placed Hermes Boots (#54) into an empty slot — fresh
  defense 0 / prefix 0; set defense 12 + prefix 65 via the CLI the GUI uses; read both
  back (12 / 65); cleared the slot. Offsets are CE-authoritative (`mono_class_enumFields`
  on `Terraria.Item`: prefix=0x15C byte, defense=0xD4 int, plus rare/type/stack/damage/
  … all matching the /proc offsets).

## Phase 4 — Code quality

- `ruff check` → passed. `prefix` writes one byte (`set_prefix`), `defense` an int
  (`set_defense`); both apply to all copies via `set_item` like the existing mutations.
  `Slot`/`ItemSlot`/JSON carry both. GUI reaches them only through the CLI contract.

## Phase 5 — Security review

- No new inputs beyond two argparse ints, range-bounded in the dialog (defense 0–9999,
  prefix 0–255). No network, no new dependencies. The new offsets are item-local reads/
  writes; a wrong offset never escapes the item object. Secrets: none.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Additive — two offsets, two data fields, two CLI flags,
  two dialog fields. No existing behaviour or offset changed. Build-specific offsets
  are documented (`docs/discovery.md`) with the mono re-derivation method.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.7.0`.
