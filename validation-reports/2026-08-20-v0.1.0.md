# Validation Report — terrariabonker v0.1.0

**Date**: 2026-08-20
**Scope**: Initial release. Specs 001 (/proc trainer core) and 002 (item editor,
tools, PyQt GUI).

## Summary

From-scratch live-memory trainer for Terraria 1.4.5.7 (Windows build under
Proton/wine-mono). Locates the player and inventory via `/proc/<pid>/mem` with no
hardcoded addresses; freezes HP/mana, edits stats, and edits inventory items
(type, stack, damage, auto-reuse, use-speed, pick, tileBoost) from a CLI and a
PyQt6 control panel. Version-gated to the known-good build.

## Phase 3 — Tests

- `QT_QPA_PLATFORM=offscreen /usr/bin/python3 -m pytest tests/ -q` → **21 passed**.
- Suite runs headless against an in-memory fake process (`tests/conftest.py`):
  no game, no root, no writes to real game memory.
- GUI verified by offscreen instantiation + a run of the event loop (rc=0).
- Live verification against the running game: from-scratch player location, HP
  editing, inventory location and item edits (dirt stack change reflected on
  screen), godmode freeze against live damage.

## Phase 4 — Code quality

- `ruff check terrariabonker/ tests/` → **All checks passed**.
- Read/write isolated in `proc.py` (no Terraria knowledge); Terraria structure in
  `locate.py` / `player.py` / `inventory.py`; views in `cli.py` / `gui/`.
- Known follow-up (spec 003): the GUI consumes the CLI's `--json` subprocess
  contract; a shared service layer with parity tests is planned to prevent view
  drift (a missing `--json` flag caused one runtime gap during development, since
  fixed).

## Phase 5 — Security review

- **Secrets**: none. Source scan for password/secret/key/token found only a
  "passwordless sudo" docstring. No credentials stored, logged, or transmitted.
- **Network**: none at runtime (grep for urllib/requests/socket/http = none). The
  bundled `data/items.json` name map was fetched once at build time.
- **Privilege**: the tool reads/writes another process's memory, which requires
  root under `ptrace_scope=1`. This is the tool's explicit purpose. The CLI
  self-elevates via sudo; the GUI stays unprivileged and shells actions out via
  sudo. No privilege is retained beyond each operation.
- **Dependency CVE scan**: dependencies are `numpy` and `PyQt6`, installed as
  system packages via pacman (`python-numpy`, `python-pyqt6`), not pip — pip-audit
  is not the applicable scanner. No third-party pip dependencies are introduced.
- **Blast radius**: single-player, local, own game process only. No external
  services, no multiplayer/leaderboard interaction.

## Phase 5.5 — Release safety

- **Rollback**: `git revert` of the commit; the tool holds no persistent state and
  writes nothing to disk, so stopping it ends all effects. Uninstall removes only a
  `~/.local/bin` symlink and a desktop entry.
- **Additive**: new subproject; touches no other project. Root README gains one row.
- **Build-specific offsets**: gated by `version.py` (refuses an incompatible
  major/minor/patch build without `--force`); the locator fails safe on a shifted
  layout (matches nothing rather than writing to a wrong address).

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.1.0`.
