# Validation Report — terrariabonker v0.5.0

**Date**: 2026-08-21
**Scope**: Spec 006 — grid inventory with a per-item edit dialog (replaces the
sortable table).

## Summary

The Inventory tab is now a grid mirroring Terraria's own layout (Hotbar /
Inventory / Coins / Ammo). Cells are text tiles (abbreviated name + stack badge,
full-detail tooltip). Clicking a cell opens a modal dialog that edits every mapped
Item property, places a fully-statted item into an empty slot, or clears a slot.
Accessories carried in the inventory edit through the identical path. The old table
and its inline cell-editing are removed.

## Phase 3 — Tests

- **66 passed** headless (7 new in `test_invgrid.py`: slot→section mapping, slot 58
  hidden, grid coverage, name abbreviation, stack badge, tooltip field selection
  including an accessory-like item). Parity test extended for the fuller
  `set_item_argv` (use-anim/pick/tile-boost and the clear-slot argv).
- Headless behavioural smoke: 58 cells build; grid fill renders labels/badges; the
  dialog resolves a same-item edit to a full-field argv and a type change/placement
  to a type+stack argv; clear sets the cleared flag.
- **Live** (game pid 1632717): placed Hermes Boots (#54, an accessory) into empty
  slot 26 — it took real ContentSamples template stats (damage -1, use_time 100);
  applied a same-type edit (use_time 30, tile_boost 5) and read it back; cleared the
  slot (type 0). All through the same CLI the GUI drives. Slot reverted to empty.

## Phase 4 — Code quality

- `ruff check` → passed. Qt-free grid logic isolated in `gui/invgrid.py` (unit
  tested); the dialog only collects values, the main window issues the CLI call, so
  CLI/GUI parity is preserved. No dangling references to the removed table widgets.
- Placement vs edit is one rule (`_apply_item_edit`): a type change sends type+stack
  so the template supplies stats; a same-item edit sends the full field set — avoids
  clobbering a freshly placed item's real stats with neutral prefill values.

## Phase 5 — Security review

- **Secrets**: none. **Network**: none. **Privilege**: unchanged — memory writes go
  through the existing sudo CLI path; the dialog adds no new privileged surface.
- **Inputs**: the item field resolves to a known ItemID or a numeric ID; an unknown
  name is rejected with a warning (no write). Spinboxes are range-bounded. `set-item`
  offsets are unchanged from prior releases.
- **Dependencies**: none added. PyQt6/numpy unchanged.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. GUI-layer change plus two additive data fields
  (`ItemSlot.use_anim`, its JSON) and one CLI-client extension. No memory offsets
  changed. A cleared/edited slot is an ordinary game value; `Clear slot` and the
  game's own item management undo it.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.5.0`.
