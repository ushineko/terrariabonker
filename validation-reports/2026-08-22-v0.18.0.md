# Validation Report — terrariabonker v0.18.0

**Date**: 2026-08-22
**Scope**: Spec 026 — auto-restore cheats and item edits on a fresh game (fixes
no-restore-on-launch and session-only item stat-edits).

## Summary

Adds a cross-session profile (`profile.py`, pid-independent) of the user's desired cheats
(+ values) and per-slot item edits, updated by the common layer on every enable/disable and
set-item. A `restore` operation (`service.restore` + `terrariabonker restore`) re-applies it
to the running game: cheats first (an anchor not yet JIT-compiled is reported `pending`, not
fatal), then item edits with a **type-match guard** so it never clobbers a slot the player
changed in-game. The GUI auto-invokes restore when a fresh in-world game is detected (any new
pid), retrying for lazily-JIT'd cheats. This makes cheats restore on any fresh game and item
stat-edits effectively persist across save/exit (Terraria saves only type/stack/prefix and
regenerates the rest from the type on load).

## Phase 3 — Tests

  absent-file); `test_service.py::test_restore_reapplies_matching_items_only` (same-type

- **Live**: `terrariabonker restore` re-applied `reach=30` to a freshly-restarted game
  (report `cheats=['reach']`). GUI trigger gating verified offscreen: fires on a fresh
  in-world pid, not on the menu (no player), and once per pid.

## Phase 4 — Code quality

- flake8 clean. `profile.py` mirrors the patch-state persistence (atomic write + flock).
  Profile updates are one-liners in the common layer (`patcher.enable/disable`,
  `cli.cmd_set_item`); `restore` is a single service method; the GUI trigger is a small
  `_maybe_restore`/`_do_restore` pair with a per-pid guard and retry cap.

## Phase 5 — Security review

- No new dependencies (`fcntl` stdlib). Restore only re-applies the user's own saved edits,
  gated by the version guard, over the existing sudo `/proc` path. The item type-match guard
  prevents overwriting unrelated inventory. Profile writes are atomic + lock-serialized. No
  secrets; no `eval`/`exec`/shell-string injection (spawns use explicit argv lists).

## Phase 5.5 — Release safety

- **Rollback**: `git revert`; delete `~/.config/terrariabonker/profile.json` to forget the
  saved config. Restore re-applies only the user's own edits and never auto-clears a slot;
  a game restart still clears live patches (which auto-restore then re-applies).

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.18.0`.
