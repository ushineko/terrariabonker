# Validation Report — terrariabonker v0.35.0

**Date**: 2026-08-25
**Scope**: Fishing (spec 042) — a rod and bait if you have none, bait that does not run
out, and a rod power that makes fish bite about once a second and is put back when the
cheat goes off.

## Summary

One new cheat, built entirely from data the game already stores. No anchor, no hook site,
no stub, nothing in the build ledger — the same shape as passive potions in v0.34.0, and
for the same reason: if a value can be read and written, there is no need to patch code to
change it.

The interesting part of this release is not the feature, it is how much of it was decided
by measurement rather than by design, and how often the measurement was wrong first.

## The part worth reading

**Three offsets, each verified against the game's own numbers.** `Item.fishingPole`
(`+0x058`) is carried by exactly seven items and every one is a rod, with the values the
game shows: Golden 50, Hotline 45, Sitting Duck's 40, Mechanic's 35, Fiberglass 30, Scarab
30, Chum Caster 25. `Item.bait` (`+0x05C`) is carried by thirteen items and no rods.
`Projectile.bobber` (`+0x088`) is true for 19 of 1100 projectile templates, including every
bobber the seven rods fire.

**A cheat was cancelled because it turned out not to exist.** The spec began with three
features; insta-fishing was the third. Hunting the "catch counter" that the community wiki
describes found nothing: not on the Player across `statLife ± 0x1200`, and not on the
bobber across its first `0x600` bytes as int or as float. One candidate at `statLife-0x49C`
looked convincing — it climbed and reset eight times in forty seconds, always with a line
in the water — and was killed by the obvious control: it keeps ticking with no line in the
water at all. The correlation existed only because the bobber happened to be out for the
whole sample.

Then the arithmetic made the search unnecessary. The published counter gains
`fishingPower / 30` per tick and fires at 660: at power 30 that is ~4.4 s between bites, at
255 it is ~1.1 s. The maintainer had already measured "a bite each second" at 255 and a
trickle at 30. **Insta-fishing and fishing power are the same lever**, so shipping two
toggles would have invented a distinction the game does not have.

**Two instruments were wrong before either gave an answer.** A probe reported zero catches
in ninety seconds while the player was demonstrably catching fish — bait fell 30 → 23 and
seven fish were in the bag afterwards. And a write of `fishingPole = 255` silently missed
because the rod's address had been cached from an earlier read and mono's GC had moved the
object; the script printed `fishingPole was 0` where 30 was expected and carried on
regardless. **Locate an item by identity on every access, and treat an unexpected
pre-value as a reason to abort.** Spec 038 already exists for the first half of that lesson.

In both cases the correction came from the maintainer watching the screen, not from the
tooling. On a live-memory project that is worth leaning on.

## In-game verification

All nine acceptance criteria on spec 042, on 1.4.5.8+24893155:

- The kit works: the maintainer threw their rod away, ticked the cheat, and was handed a
  Golden Fishing Rod. Run against a player who already had gear it gave nothing.
- Bait held: two stacks topped in one round (15 → 30, 3 → 30) and held through continuous
  fishing.
- **One catch a second at power 255**, against a trickle at the same rod's own 50.
- **The rod was put back**: it reads 50 again, not 255, and the profile has no pending
  restore left — checked by reading memory, not by eye.

## Security review (Phase 5)

- No `eval`/`exec`, no `subprocess`, no sockets, no network calls in shipped code.
- No hardcoded credentials.
- Dependencies unchanged since v0.34.0, so `pip-audit` was not re-run.
- Writes stay inside the player's own process: a byte per rod, a stack per bait, and the
  items the kit gives. One new file is written outside the game — the record of each rod's
  original power, in the existing profile JSON under the user's config directory.

## Release safety

- **Rollback**: `git revert` or check out the previous tag. Nothing is patched.
- **The one lasting change is by design and is reversible in the program**: rod power is
  written into the save. Its original is recorded on disk *before* the rod is written, so
  a trainer killed mid-cheat leaves a spare record rather than an unrecoverable rod, and
  the panel restores anything owed on its next start.
- Everything else evaporates when the trainer closes. Given items and topped-up bait stay,
  as any given item does.

## Known gaps

- **Auto-catch is not built.** Reeling in is still a manual click. The spec records the
  maintainer's suggested route — drive the player's generic use-item control rather than
  the fishing path — a candidate at `statLife-0x00c6` that holds while the button is down,
  and the fact that writing it did not cast a line. Two explanations are recorded, and the
  next experiment named, rather than one being guessed at.
- **The 125-vs-255 ceiling was never A/B tested.** 255 is shipped on the maintainer's call
  and on evidence that it out-fishes what a 125 cap would allow, but the controlled
  comparison was not run.
- **Item offsets are build-specific** and would need re-deriving after a game update.
  Nothing goes in the build ledger because that records anchors and this cheat patches no
  code; `docs/item-fields.md` records how the offsets were found.
