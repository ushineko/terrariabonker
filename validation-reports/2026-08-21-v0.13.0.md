# Validation Report — terrariabonker v0.13.0

**Date**: 2026-08-21
**Scope**: Spec 017 — map-ping teleport (managed-call code cave hooking
`Main.TriggerPing` → `Player.Teleport`), the project's first code cave that *calls* a
managed method rather than forcing a value.

## Summary

New `teleport` injection: a stub hooked at `Main.TriggerPing+0x2D` reads the ping's tile
coordinates, scales them ×16 to world pixels (add `0x02000000` to the float bits —
exponent += 4, no FPU/constant), and **calls** `Player.Teleport(this, x, y, 0, 0)` on the
local player. With it on, a fullscreen-map **double-click** warps the player there.
Ported from the FearLess ReGrind table; the 1.4.5.7 sites were re-derived. Two AOBs are
resolved at enable time: `trigger_ping` (inject site) and `player_teleport` (call target
= match − 0x32). `this` is the `resolve_local_player` object base (`life_addr −
STATLIFE_FROM_OBJ`), not the raw scan (which can return inert snapshots). esp is
saved/restored via `ebx` so the stub is agnostic to mono's caller/callee stack cleanup.
The `Injection` dataclass gained `call_anchor`/`call_target_off`; the value-force
injections are unchanged.

## Phase 3 — Tests

- **92 passed** headless. New: `test_teleport_managed_call_stub` (AOB resolve, baked
  `this` = `life_addr − STATLIFE_FROM_OBJ`, call target = `player_teleport − 0x32`, the
  two ×16 adds, enable/disable roundtrip) and `test_teleport_stub_is_stack_convention_agnostic`
  (esp saved/restored via ebx, no `add esp` guess, ×16 present).
- **Live** (game pid 1632717): both AOBs validated read-only — `trigger_ping` unique at
  `TriggerPing+0x2D`, `player_teleport` unique with the Teleport prologue at entry−0x32,
  inject bytes match. A read-only diagnostic hook captured the ping coords `(3501.84,
  334.69)` vs the player object's `(54445.78, 5782.0)` px, proving the coords are **tiles**
  (→ the ×16 fix). The fixed stub was installed via the CLI path and verified byte-for-byte
  (correct `this`, Teleport target, ×16 adds, jmp-back). **User confirmed teleports land
  "spot on" with no crash across many pings.**

## Phase 4 — Code quality

- flake8 clean (`--max-line-length=100`). The managed-call path is a small branch in
  `_enable_injection` (build body from resolved addresses vs `make_body(value)`);
  everything downstream (cave borrow, jmp-in/out, state persistence) is reused unchanged.
  `STATLIFE_FROM_OBJ` is imported from `locate` rather than duplicated. No dead code.

## Phase 5 — Security review

- No new external dependencies (only a wider import from the internal `locate` module).
  No secrets; no `eval`/`exec`/shell/subprocess/network in the new code. The stub is
  generated purely from addresses resolved out of the game's own memory — no external or
  user input reaches the codegen (the injection `value` is ignored for teleport). Written
  over the established sudo `/proc` path into borrowed executable padding; fails safe on an
  AOB miss ("anchor not found", no write). Dependency set unchanged (numpy, PyQt6) — no
  scanner delta. `ce/poc_teleport.lua` is a dev-only CE recon script (not runtime).

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Disable restores the 7 displaced bytes at the inject site
  and scrubs the cave; a game restart clears the patch. Known caveat (documented):
  `player_base` is baked at enable time, so re-toggle after a world/character reload; the
  address was stable across the whole test session. The inject anchor sits at the method
  tail so, like the other injections, a re-scan after the jump is in place reports
  "not found" rather than mis-writing.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.13.0`.
