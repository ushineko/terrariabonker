# Validation Report — terrariabonker v0.31.0

**Date**: 2026-08-23
**Scope**: Spec 039 — pick an item's template by consensus, not by where it sits.

## Summary

`find_item_templates` could return a live, modified item as an item's pristine template. It
is the root cause behind the v0.30.1 incident, and it was also feeding the Compendium wrong
base stats. Fixed by deciding a template by agreement between copies rather than by address.

## The part worth reading

The old rule chose by position: cluster Item objects by address, keep the types appearing
exactly once in each run, biggest run first. Nothing in that distinguishes a pristine copy
from a modified one, and a type appearing twice inside the big run is excluded from it — so
a smaller run supplies the value instead.

**The contaminants were not the player's items.** The maintainer asked where a Muramasa was
coming from, having none. Four exist in memory: the template (damage 24, no prefix) and a
**Superior copy sitting in a world chest** (damage 26). Terraria generates chest weapons
with random modifiers and keeps every chest in memory, so the scan was reporting a chest
weapon's rolled stats as the item's base stats. Same for a Godly Wooden Boomerang and a
Legendary Ice Blade.

Two structural signatures were tried against the live game and rejected: the templates are
**not** evenly spaced (zero chains of more than 50 objects at a constant stride) and are not
confined to a single address run.

What does distinguish them is agreement. Three rules, in order:

1. **Exclude the player's own items by address** — `Inventory._item_addr` gives them
   exactly, and they are what this program edits.
2. **Prefer unprefixed copies** — a modifier changes damage and use time, so a prefixed copy
   is not a template.
3. **Take the consensus** — the most common stat tuple. A pristine template agrees with
   every other pristine copy; a modified one stands alone.

NPC templates get the same treatment: the live `Main.npc` objects are excluded by address,
since their stats have been scaled by the world's difficulty.

## Phase 3 — Tests

- **356 passed** headless, up from 353.
- `tests/test_content.py`: copies that agree are the template; one modified copy does not
  outvote the pristine ones; a prefixed copy never wins over an unprefixed one; the prefix
  is not reported as a stat; excluded objects are not considered.
- The two tests encoding the positional rule were **replaced, not adjusted** — the rule they
  described is the one that caused the bug.
- **Both new rules are mutation-checked.** The exclusion test had to be rewritten to earn
  it: the first version passed even with exclusion disabled, because its two candidates tied
  and the tie resolved the same way by luck. The excluded copies are now the majority, so
  ignoring them changes the answer.

Live, against values known independently of this project:

| item | before | after |
| --- | --- | --- |
| Boomstick | 31 / 12 (the maintainer's own edit) | **14 / 40** |
| Book of Skulls | 45 / 12 (the maintainer's own edit) | **29 / 32** |
| Muramasa | 26 (a Superior copy in a chest) | **24** |
| Wooden Boomerang | 11 (a Godly copy) | **10** |
| Ice Blade | 20 / 49 (a Legendary copy) | **17 / 55** |
| Slime Whip | 15 / 30 | unchanged, already correct |

Coverage improved rather than regressed: 6,157 types before, **6,161** after, in 3.7 s.

## Phase 4 — Code quality

- The clustering helpers stay, used by NPCs, where the run rule is verified and live objects
  are excluded by address instead.
- `prefix` is read into the stats only to tell a modified copy from a pristine one, and
  stripped before the result is returned — a test pins that.
- flake8 clean on changed files; the same pre-existing hits remain in untouched lines.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no new dependencies. `pip-audit 2.10.0`: *No known
  vulnerabilities found*.
- No new memory writes; this is a read path only. The extra field read is inside the span
  already being read per object.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`; the template cache regenerates from the running game in ~4 s.
- Existing caches are stale in content but not in shape, so they are **not** auto-invalidated
  by the shape check. Anyone wanting corrected stats immediately can use the Compendium's
  **Re-scan from game**, or delete `~/.cache/terrariabonker/templates-*.json`.

## Known limitations

- **Consensus can be wrong where every copy is modified.** A chest of forty identically
  edited swords with no pristine copy would carry the vote. The alternative — believing an
  arbitrary copy — is what happened before.
- **A type whose only object is the player's edited one** is now absent from the catalog
  rather than wrong. Absent is the honest answer.
- **Two copies disagreeing with no prefix to separate them** is a tie, resolved by address
  order. Rare, and no worse than before.

## Result

Gates pass. Approved for commit and tag `v0.31.0`. Spec 039 COMPLETE.
