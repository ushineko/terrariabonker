# Validation Report — terrariabonker v0.9.1

**Date**: 2026-08-21
**Scope**: Spec 011 — read the live player by ground truth
(`Main.player[Main.myPlayer]`). Fixes the trainer showing a stale player copy.

## Summary

The inventory/status view could show a stale snapshot copy. Cause: `pick_live`
samples `statLife` for activity, which is static at full HP (and the game is paused
whenever the trainer window has focus), so it returned `None` and the service fell
back to "richest inventory" — which a frozen snapshot can win (live 15 items vs stale
37). Fixed by resolving the actual live player via `Main.player[Main.myPlayer]`,
AOB-found through `Main.get_LocalPlayer`, which is correct regardless of pause state.

- **79 passed** headless (2 new in `test_localplayer.py`: resolve from a planted
  `get_LocalPlayer` + `Main.player`/`myPlayer` + player object; missing-pattern returns
  None so callers fall back to the scan).
- **Live** (game pid 1632717): `resolve_local_player` returned the live copy
  (0xbd6b780), and `inventory` then matched the in-game inventory (Torch ×213, Wood,
  Campfire, Abigail's Flower) instead of the stale snapshot (Torch ×216, Cloud, Grass
  Seeds). Derivation confirmed: `Main.myPlayer=0`, `Main.player[0]`+0x738 = the live
  statLife.
