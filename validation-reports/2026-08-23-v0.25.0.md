# Validation Report — terrariabonker v0.25.0

**Date**: 2026-08-23
**Scope**: Spec 035 — item compendium tab, **Phase 1 of 3** (catalog and browsing).

## Summary

A Compendium tab listing every item in the game (6,195) and every NPC name (763), filterable
by kind and by name or ID, sortable on damage / defense / rarity / ID, showing each item's
sprite, kind, the game's own tooltip text, a wiki link, and a Give button.

At the maintainer's request the feature is split into three phases with a validation stop
after each. Phase 2 (NPC stats, real kinds, `NPC.SpawnOnPlayer`, placement offset, boss gate)
and Phase 3 (NPC sprites) are open; spec 035 stays INCOMPLETE and its acceptance criteria are
now grouped by phase.

## The part worth reading

**The spec's primary approach was deliberately rejected, and the fallback shipped.**

Item stats are not in `Terraria.exe` in any readable form — `Item.SetDefaults` assigns them at
runtime — so the authority is `ContentSamples.ItemsByType`. `Item.get_OriginalDamage` shows it
is a `Dictionary<int, Item>`, and the spec named walking that dictionary as the primary route.

Walking it means depending on **mono's** field layout, not Terraria's. That is the one failure
mode this project has no defence against: the spec-030 build ledger is keyed on the game's
version + Steam buildid, so a mono runtime update could break the walk silently, with the
ledger reporting everything verified.

The shipped route (`content.find_item_templates`) depends only on Terraria's own object
layout. It scans the writable regions for objects carrying the `Item` vtable — the scan
`_template_block` already does for one type — and then identifies the template table by its
**shape**: templates are one object per type, while live items (inventory, chests, dropped
items) repeat types heavily. Addresses are clustered into runs (`CLUSTER_GAP = 0x400000`), and
a run is a template table when it holds about one object per distinct type
(`ONE_TO_ONE = 1.05`); the largest such run wins, so a chest that happens to look one-to-one
cannot outrank the real table.

Measured live: **169,637 Item-shaped objects in 463 ms**, whose one-to-one runs cover **6,162
distinct types** — every item with a template.

**Six field offsets were derived by differencing templates**, not by reading IL: `healLife
0xB4`, `healMana 0xB8`, `headSlot 0xD8`, `bodySlot 0xDC`, `legSlot 0xE0`, `buffType 0x130`.

**One classification bug is worth recording because the fix caused a second one.** The
maintainer reported the potion list looked incomplete: filtering on `healLife`/`healMana`
found 16 potions, because buff potions carry neither — they carry `buffType`. Adding
`buffType` took potions to 236 and silently reclassified **28 summon staffs as potions**, a
staff granting its minion as a buff. The damage test now runs before the buff test, and both
directions are pinned by tests.

## Phase 3 — Tests

- **269 passed** headless, up from 233 at v0.24.0 (36 new + 6 for the cache-ownership fix).
- `tests/test_content.py` (18): one template per type; non-Item objects and absurd type values
  ignored; a repeated-type run is not mistaken for the table; the larger table wins when a
  type appears in two; the kind ladder in both directions (accessory beats damage, vanity
  armour with no defense is still armour, tool beats weapon, weapons split by damage class,
  block before material, **summon staff is a weapon not a potion**, **buff potions are
  potions**); wiki URL shape; no unresolved localization references in item or NPC names.
- `tests/test_compendium_tab.py` (8): a double-click opens **exactly one** dialog — the test
  emits both `doubleClicked` and `activated`, which is the bug it exists for; rows carry
  name/kind/stats/id; kind filter and name-or-ID search narrow the list; ID sorts numerically;
  blank stat cells still sort by their real value; the last column does not swallow the slack;
  numeric headers are right-aligned like their values.
- `tests/test_uitext.py` (7): notes wrap within the tooltip width, blank lines survive, source
  line breaks are re-flowed, every cheat note stays tooltip-sized and does not repeat what the
  group tooltip says.
- `tests/test_gui_construct.py` (3): the window builds with every tab, every cheat has a
  checkbox, patches are split into section tabs. **This file exists because the GUI failed to
  start** after the Compendium tab was added — a log callback was bound to a widget built
  later — and the smoke test was confirmed to catch that bug before the fix landed.
- `tests/test_cache_ownership.py` (6): the ownership guard in all four states, a chown failure
  is survivable, and the cache write path calls it for both the directory and the file.
  Confirmed load-bearing by removing the two calls and watching the test fail.
- **Live, maintainer-validated over several rounds**, each round changing the design: the icon
  grid clipped names and was replaced by a sortable list; stat columns were added for sorting;
  the potion gap was found in play; header/value alignment was corrected; cheat tooltips were
  rewritten and split into section tabs.

## Phase 4 — Code quality

- The compendium reuses the existing filter-proxy and sprite-cache machinery. It does **not**
  reuse the recipe icon grid: a grid cell cannot show a full item name plus its kind without
  clipping one, and 6,958 entries are browsed by name. Recorded in the spec, since the spec
  had specified the grid.
- `setStretchLastSection(False)` with Name as the stretching column. Qt stretches the last
  section by default, which handed ID the whole slack and stranded its header from its
  right-aligned values — the maintainer's alignment report.
- Only `doubleClicked` is connected. `activated` also fires for a double-click here, and a
  re-entrancy flag does not help: `exec()` runs a nested event loop, so the second signal
  arrives *after* the dialog closes and opens another. Enter is a separate `QShortcut`.
- The extractor's localization resolver was generalised from `CommonItemTooltip.*` to any
  `{$Category.Key}`: unresolved references went 19 → 0 in NPC names, 534 → 5 in tooltips,
  2 → 0 in item names.
- All 12 cheat notes rewritten to tooltip length and re-flowed through `gui/uitext.wrap`; the
  stale placement-reach note (which described the smart cursor before that cheat existed) was
  corrected.
- flake8 clean at the project's ~100-col convention on all changed code. Three pre-existing
  hits remain in untouched lines (`cli.py:470`, `gui/client.py:19`, `gui/main_window.py:298`);
  verified present at HEAD before this work and left alone.

## Phase 5 — Security review

- No `eval`/`exec`, no `pickle`, no `shell=True`, no `os.system`. (The `exec()` matches in the
  GUI are `QDialog.exec()` / `app.exec()` — Qt event loops.)
- **No network call originates in the app.** The wiki button hands the URL to
  `QProcess.startDetached("xdg-open", [url])` — its own argv element, no shell. The scheme and
  host are a hardcoded prefix, so the string is always a well-formed `https://terraria.wiki.gg/`
  URL; names come from the game's own localization data.
- **Path safety of the cache key**: `build_key()` is interpolated into the cache filename.
  Both halves are constrained at their source — the version by a digits-and-dots regex, the
  Steam buildid by `(\d+)`, each falling back to `?` — so no separator or `..` can reach the
  path.
- **Finding, fixed in this release**: the privileged worker wrote the template cache into the
  user's own `~/.cache/terrariabonker/` (sudo -E keeps `HOME`) but owned by `root`. The user
  could not clear their own cache, and root was parsing a file in a user-writable directory.
  Impact was bounded — the cache feeds the compendium *display* only, `give_item` does its own
  live template scan and never reads it, and `json.load` executes nothing — but it is now
  fixed: `proc.give_back_to_user()` chowns the directory and file to `SUDO_UID`/`SUDO_GID`,
  best-effort. The pre-existing root-owned file was removed so the fix takes effect.
- No new dependencies. `pip-audit 2.10.0`: *No known vulnerabilities found*.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. The tab is purely additive and reads memory only; nothing in
  Phase 1 writes to the game except the pre-existing `give_item` path.
- **No new patches, no ledger entries.** Phase 1 adds no AOB anchors and no code caves; the
  spawn injection is Phase 2 work.
- **Disposable state**: the template cache regenerates from the running game in ~2 s.
- **No save-format change.**

## Known limitations

- **Spec 035 remains INCOMPLETE**, by design: Phase 2 (NPC stats, spawn, boss gate) and
  Phase 3 (NPC sprites) are open. Every NPC currently reports kind `NPC`, because the flags
  that distinguish town/boss/monster need `Main.npc`.
- **Two Phase 1 criteria are unverified live**: the **Wiki** and **Give** buttons on a
  compendium entry. Both reuse paths that work elsewhere and both are unit-tested for shape,
  but neither has been clicked in a running session. Recorded unchecked rather than assumed.
- **Five tooltips still carry an unresolved localization reference** and render the raw token.
- **Spec 034 still has its one open criterion**: `SmartCursorLookup` behaviour before it is
  JIT-compiled, pending a fresh game launch.
- **Not a defect, resolved by investigation**: the faint horizontal line the maintainer
  reported between Max HP and Max mana is not drawn by the app. It is a uniform +5 grey across
  the entire client width — over the group-box interior *and* the window background — sitting
  in the gap between two grid rows. Rendering the same window through Qt under Oxygen at the
  maintainer's 1.5× scaling reproduces every real group-box border and no such row, so it
  comes from the style's window-background painting on a composited window, not from any
  widget. The GUI sets no palette, no window background and no translucency.

## Result

Gates pass. Approved for commit and tag `v0.25.0`, with Phase 1 of spec 035 complete and
Phases 2–3 recorded as open.
