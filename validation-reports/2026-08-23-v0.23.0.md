# Validation Report — terrariabonker v0.23.0

**Date**: 2026-08-23
**Scope**: Spec 033 (accessories take effect from the inventory), the patch-list section
re-org, and a diagnosed smart-cursor performance interaction recorded in the reach tooltips.

## Summary

Spec 032 made the vanity accessory column functional by widening two loop bounds, because
those slots already lived in `armor[20]`. The inventory needed a different shape: its items
are in another array entirely, so the item *source* had to change, not a bound.

`UpdateEquips`' first loop already walks all 58 inventory slots every frame — vanilla uses it
to refresh info and mechanical accessories, which is why a Depth Meter has always worked from
the bag. The cheat hooks the point where the `Item*` is already in `eax` and calls the three
methods an equipped accessory goes through: `ApplyEquipFunctional`, `GrantPrefixBenefits` and
`GrantArmorBenefits`.

Cost is controlled by testing `Item::accessory` (+0x7D) before calling anything, so the
11.6 KB `ApplyEquipFunctional` runs only for items that are actually accessories.

Also in this release: the eleven code patches are grouped (Build / Combat / Accessories /
Misc) rather than one flat list, and the two reach cheats now warn in their tooltips about
the smart-cursor interaction diagnosed below.

## Phase 3 — Tests

- **215 passed** headless, up from 201.
- `tests/test_inventory_accs.py` (9): call targets read from the anchored call sites; the site
  takes a jump and disable restores it; the stub tests `item.accessory` before calling
  anything; all three methods are called; `pushad`/`popad` with `esp` restored from `ebx`
  after each call; the `je` lands exactly on the reproduced `mov eax,[eax+0x6c]`; the stub
  jumps back to the right address; the anchor still resolves with the cheat applied; disable
  scrubs the cave.
- `tests/test_build_ledger.py` +3: every cheat lands in a section, a cheat missing from the
  section map is not hidden, and the catalog is ordered so section headings cannot repeat.
- The stub was disassembled against the live game before enabling: `je 0x31` landing on the
  reproduced instruction, and all three call targets matching addresses seen independently in
  the original disassembly.
- **Live, maintainer-verified**: accessories carried in the inventory granted their effects
  unequipped; moving a Warding accessory out of a vanity slot into the bag kept its defense
  contribution, isolating the `GrantPrefixBenefits` call; disabling restored the displaced
  bytes and stopped the effects — both directions exercised on a site executing 58 times a
  frame, with the game running throughout.
- **Cost measured**: 4 interleaved A/B samples of the game process's CPU — off 105.9%
  (stdev 1.9) vs on 104.4% (stdev 1.6) of one core, a −1.6 point delta against ~1.9 points of
  noise. A first attempt comparing two long blocks was inconclusive because the game's own
  workload drifts by more than the effect; interleaving fixed that.

## Phase 4 — Code quality

- `_call_target` reads a callee's entry from the rel32 of an *already anchored* call, so no
  new anchors were needed for the three methods — reusing what spec 032 verified.
- The stub follows the teleport stub's discipline (`pushad`/`popad`, `esp` from `ebx`) rather
  than a hand-rolled scratch frame, because mono emits `ret N` for some methods and a
  `sub esp`/`add esp` pair would double-count. The spec was corrected to describe what was
  built; it had specified the earlier design.
- `Injection.build_body` generalises the one-off teleport special case into a hook any
  injection can use to build its stub from live state.
- Sections live in `patcher.SECTIONS`; a cheat missing from the map falls into the last
  section rather than vanishing, and the catalog is ordered so CLI and panel agree.
- flake8 clean at the project's ~100-col convention on changed files.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no new dependencies. `pip-audit 2.10.0`: *No known
  vulnerabilities found*.
- The stub contains no user input: three call targets read from the game's own code, and
  fixed opcodes. The cheat takes no tunable value.
- Writes are confined to resolved anchor sites and borrowed int3 caves through the existing
  machinery; disable restores the bytes and scrubs the stub.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`; both accessory cheats are off by default and disable restores
  the original bytes. A game restart clears them.
- **No save-format change.** Only whether the game reads items it already stores.
- **Ledger**: `inventory_scan` is recorded as verified on `1.4.5.7+24893155` only — derived on
  that build and confirmed in-game there, never seen on the original build.

## Diagnosed, not fixed here — smart cursor vs reach

Holding Shift to auto-place collapses the frame rate with the reach cheats set high.
`SmartCursorHelper.SmartCursorLookup` sizes its search box from `GetTileRegion`, which calls
the `GetRanges` that `tool_reach` forces and then adds `blockRange` on top. The box is an
area, so cost is quadratic: ~121 tiles/frame at vanilla-ish reach, 22,801 at 75, and roughly
90,000 with both cheats stacked. Confirmed by experiment — severe at 75, gone at 20.

The clamp cannot live in `GetTileRegion` (nine callers, including `IsInTileInteractionRange`
and `AdjTiles`, which are what `tool_reach` exists to extend), so it belongs inside
`SmartCursorLookup`. That is spec 034. For this release the two reach tooltips explain the
relationship so the next person does not have to diagnose it.

## Known limitations

- **Stacking is unbounded**: forty of the same accessory in the inventory apply forty times.
  Vanilla never had to dedupe a case it did not expect. Intended for a trainer, but it is a
  behaviour change.
- **Visual coupling**: every inventory accessory follows `hideVisibleAccessory[0]`.
- **Bank containers** (piggy bank, safe, Defender's Forge) are not covered; nothing in
  `UpdateEquips` iterates them. The Void Vault does have an existing loop and is the cheapest
  next addition.

## Result

All gates pass. Approved for commit and tag `v0.23.0`.
