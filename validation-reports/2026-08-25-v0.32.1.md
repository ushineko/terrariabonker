# Validation Report — terrariabonker v0.32.1

**Date**: 2026-08-25
**Scope**: The arena bootstrap hooked the wrong byte, which killed the game on launch for
anyone with the ore extractor in their profile. Introduced and shipped in v0.32.0.

## Summary

`Patcher.arena()` borrows the extractor's injection site for the springboard that calls
`VirtualAlloc`. It resolved the anchor but never added `inject_off`. That was correct while
the extractor hooked `PickTile` at offset 0, and became a jump written **0x15 bytes early**
the moment the hook moved to `grabitems_call` — whose match begins 0x15 before the site.

The jump landed in the middle of `Player.Update`'s dead-check, a method that runs every
frame, so the game died instantly. Auto-restore enables the cheat on every launch, so the
trainer appeared to be comprehensively broken by a game update.

## The part worth reading

**It looked like a new build, and was not.** The morning's evidence had to be cleared away
first:

| suspected | actual |
| --- | --- |
| Terraria updated | exe mtime 2026-08-23, same inode, same buildid `24893155` |
| Proton broke codegen | Proton did update, but the proton and wine hashes are unchanged and wine-mono is still 11.2.0 — only the graphics layers moved |
| a cave landed in live memory | all 12 caves land in mono's JIT arena, in int3 padding, as always |

What gave it away was `grabitems_call` resolving during `build-check` and then matching
nothing minutes later, in the same process. Locating the call site by scanning for calls to
`GrabItems` instead of by pattern showed why:

```
today:     89 04 24 8b c0 00 00  85 c0 75 14 ...
expected:  0f b6 80 d8 05 00 00  85 c0 75 14 ...
           ^^^^^^^^^^^^^^ the extractor's own overwrite bytes, 0x15 too early
```

The corruption was the restore half of the same bug: a jump written at the wrong address is
put back at the wrong address, leaving `overwrite` where it never belonged.

**The diagnostic reproduced the fault.** Computing "where would each cave land" called
`build_body`, which calls `arena()`, which hooked the game again. The running world was
repaired by hand before continuing.

## The fix

1. `arena()` adds `inject_off`, as every other caller does.
2. **`_check_site` — refuse to write a jump over bytes we would not put back.** A 5-byte
   jump goes over live code and the original is replayed from `overwrite`; if the address
   is wrong, both halves are wrong. Reading the site first costs one read and turns a
   corruption into an error naming the address and both byte strings. Applied to the
   bootstrap and to the first enable of every injection.
3. The bootstrap's failure message said "the game needs one pickaxe swing", which stopped
   being true when the hook moved to a per-frame site. It now says what is actually wrong —
   the game is not advancing frames, because Terraria pauses when its window loses focus —
   and the wait drops from 300s to 20s, since a five-minute block during auto-restore is
   not acceptable.

## Phase 3 — Tests

- **397 passed** headless, up from 395.
- `arena()` must add `inject_off`; mutation restoring the bug is caught.
- `_check_site` refuses mismatched bytes and names both; mutation neutering the check is
  caught.
- Verified live, with the game running: enabled in **1.6s**, arena at `0x68000000`
  (`rwxp`), hook installed, game healthy, clean disable and byte-exact restore.

**A false negative worth recording.** The first live attempt failed and looked like the fix
had not worked. The liveness probe was wrong: it sampled the player's position and velocity,
which do not change when the player stands still. Sampling Main's statics (94 bytes ticking
per second) showed the game running normally. The lesson is the probe, not the fix.

## Phase 4 — Code quality

- `_check_site` is one method used by both write paths rather than a check duplicated at
  each call site.
- Only on a first enable: a re-apply writes over its own jump, and the displaced bytes are
  in the stub by then.
- flake8 clean on changed files.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no dependency changes (clean at v0.32.0).
- This release *removes* a memory-safety hazard: the write path now refuses an address
  whose contents are not what it would restore.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. v0.32.0 is the broken state, so rolling back past this
  reintroduces the crash; roll forward instead.
- **Anyone on v0.32.0 with `ore_extract` saved should update before launching**, because
  auto-restore applies it on every launch and the crash is immediate.

## Known limitations

- **The bootstrap needs the game unpaused.** Terraria pauses in single-player when
  unfocused, so enabling the extractor while tabbed out fails after 20s with that message.
- **The panel does not protect the game from a cheat that kills it.** Auto-restore applied
  a cheat that crashed the process instantly and nothing caught it. Out of scope here.
- **Eleven cheats still use borrowed padding.** They resolved correctly today, but the
  technique remains a heuristic against a memory map that moves.

## Result

Gates pass. Approved for commit and tag `v0.32.1`.
