# Validation Report — terrariabonker v0.18.1

**Date**: 2026-08-22
**Scope**: Spec 027 — auto-restore timing/display fixes + checkbox no-flicker.

## Summary

Three fixes found by a clean-room launch-from-TB test of the v0.18.0 auto-restore:
(1) auto-restore now retries while item edits are still skipped (the inventory populates a
few seconds after world-entry), so item edits re-apply once it's loaded; (2)
`Patcher.values()` falls back to the saved profile so value spinboxes show the user's saved
values on a fresh game instead of spec defaults (and a toggle no longer re-applies a
default); (3) `_render_patches` no longer flips a queued/mid-apply checkbox from an
in-flight status refresh (track `_cheat_inflight`, skip queued/in-flight cheats in render).

## Phase 3 — Tests

- **119 passed** headless; flake8 clean.
- Offscreen: the flicker fix — an in-flight checkbox stays as the user set it during an
  in-flight refresh, and reflects ground truth once confirmed.
- **Live clean-room relaunch**: profile saved correctly (9 cheats + reach/tool_reach/pickup
  75, spawn 2, loot 2, plus two item edits). After launch-from-TB and world-entry, all 9
  cheats applied with correct values, and both edited items re-applied exact stats (Slime
  Whip slot 0: type 5688 / dmg 45 / useTime 30; Boomstick slot 1: type 964 / dmg 30 /
  useTime 12).

## Phase 4 — Code quality

- flake8 clean. Small, targeted changes: a retry-condition broadening in `_do_restore`, a
  precedence tweak in `Patcher.values`, and an `_cheat_inflight` guard in `_render_patches`.

## Phase 5 — Security review

- No new dependencies, no network, no new writes. `values()` now also reads the profile file
  (already read/written by the profile subsystem). No secrets; no `eval`/`exec`/shell.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. GUI display/retry + one common-layer read-precedence change;
  no new game-write behaviour.

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.18.1`.
