# Validation Report — terrariabonker v0.14.0

**Date**: 2026-08-22
**Scope**: Spec 018 — recipe-browser overhaul: a crafting-style icon grid with live
filtering and an ingredient popup, backed by a self-contained item-sprite decoder.

## Summary

The Recipes tab is now a Terraria-crafting-style **icon grid** of craftable items with a
real-time search filter (name or ItemID) and a click-through popup detailing each recipe's
ingredients (icon + count) and crafting station; the Makes/Uses toggle is retained. Item
sprites are decoded from the game's own `Content/Images/*.xnb` by a vendored decoder
(`xnb.py`: XNB container + a port of the libmspack/MonoGame **LZX** decompressor +
Texture2D SurfaceFormat.Color) — no external tools, no node. `sprites.py` caches the
decoded PNGs under `~/.cache/terrariabonker/<version>/`, learns the game's content path
from the running process, and extracts unprivileged (disk read only). The grid is built
from recipe outputs, fixing the prior bug where the name autocomplete offered
non-craftable items (e.g. paintings).

## Phase 3 — Tests

- **101 passed** headless (9 new). `test_xnb.py`: 7-bit int, a deterministic
  uncompressed-XNB Texture2D round-trip (pixel values checked), unsupported-format and
  non-XNB raise `XnbError`, and a real-file LZX decode (skips when the game isn't
  installed). `test_sprites.py`: referenced-item union (outputs + ingredients),
  version-scoped cache paths, content-dir persistence/reload.
- **Live**: `extract-sprites` decoded **3697 of 3757** referenced icons (~1.9 ms/file); the
  60 skips are item IDs with no `Item_<id>.xnb` on disk — zero decoder errors, covered by a
  placeholder icon. An offscreen render confirmed the 3214-item Makes grid, live filter
  ("sword" → 32 matches), and the ingredient popup (Torch → Gel ×1 + Wood ×1) rendering
  real sprites.

## Phase 4 — Code quality

- flake8 clean on all new/changed files (the only warnings are pre-existing long lines in
  untouched code, left per surgical-change policy). New modules `xnb.py` and `sprites.py`
  are cohesive; the GUI reuses the existing QProcess pattern (a new unprivileged variant
  for disk-only work). `STATLIFE_FROM_OBJ`-style constant reuse; removed now-unused
  `QCompleter`/`QListWidget` imports left by the old text list.

## Phase 5 — Security review

- **New dependency**: Pillow (imaging). Recorded version: Pillow 12.3.0 (system python).
  `pip-audit` is not installed in the project's python (`/usr/bin/python3`); dependency
  CVE scanning not run there — noted as a limitation. numpy/PyQt6 unchanged.
- **Inputs**: the user's own local game files (trusted) and the tool's own generated PNGs
  — no network or untrusted input. No secrets; no `eval`/`exec`/shell. The GUI spawns the
  CLI via `QProcess` with an explicit argv list (no shell), and sprite extraction runs
  **without** sudo (disk + `/proc/<pid>/maps` only), so the cache is user-owned.
- **Robustness hardening**: `sprites.extract` now skips *any* malformed/unsupported sprite
  (broadened from `XnbError/OSError/ValueError` to catch `struct.error`/`IndexError` too),
  so one bad file can never abort the batch; the GUI falls back to a placeholder icon.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. No game memory is touched by this feature (disk read + GUI
  only). The icon cache is disposable: `rm -rf ~/.cache/terrariabonker/`. The learned
  content path lives in the same cache tree. Nothing icon-related is committed
  (copyrighted assets stay in the user's cache).

## Result

All gates pass. Approved for commit and tag `terrariabonker/v0.14.0`.
