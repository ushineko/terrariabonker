# Validation Report — terrariabonker v0.26.0

**Date**: 2026-08-23
**Scope**: Spec 035 — item compendium, **Phase 2 of 3** (NPC stats, real kinds, spawning).

## Summary

NPCs get the treatment items got in v0.25.0, plus the ability to spawn them. Every one of the
759 NPCs now carries life / damage / defense and a real kind — 22 bosses, 60 town NPCs, 111
critters, 566 monsters — and a **Spawn** button places one behind the player at a chosen
distance. Bosses are gated twice: a confirmation naming the boss, then a five-second countdown
with a Cancel button.

Phase 3 (NPC sprites) remains open, and spec 035 stays INCOMPLETE.

## The part worth reading

**The spec's spawn design was dropped, and recon is why.**

It called for a managed-call injection of `NPC.SpawnOnPlayer(Main.myPlayer, type)`. Reading
the IL corrected that twice over:

1. The method takes **six** arguments, not two — `(int plr, int Type, float, float, float,
   float)`. Three independent call sites agree (`ItemCheck_UseBossSpawners`,
   `WorldGen::CheckOrb`, `SpawnMechQueen`), all pushing four float zeros.
2. Those floats are **not** a spawn offset, which would have given placement for free.
   `SpawnBoss` passes them straight through to `NewNPC` as `ai[0..3]`.

The deeper problem is that a managed call has no trigger here. The teleport stub is driven by
a player action it already hooks; an on-demand spawn would have meant a stub sitting in a
per-frame method polling a flag written from outside — live JIT patching in a hot path.

None of that is necessary. `give_item` has placed fully-statted **items** since v0.2.2 by
copying a ContentSamples template into a slot, and every `Main.npc` slot is a real NPC object
allocated at world load. So a spawn is the same trick one level up: copy the template over an
unused slot, set the position, write `active` **last** — until that byte is set the game skips
the slot, so it never sees a half-built NPC. No cave, no managed call, no ledger entry, and
nothing that outlives the session.

**What the copy must not copy.** Reference fields (`0x044..0x06F`) are skipped, or the spawned
NPC would share the template's arrays. A first pointer map also flagged `0x080..0x08F`; those
are floats (0.5, 0.25, 0.375) whose bit patterns land in a readable region. Copying them as
references would have been exactly the bug the rule exists to prevent — caught by checking the
targets rather than trusting the heuristic.

**Two defects came out of the maintainer's review**, both from one symptom: a thinly populated
`NPC` category holding 8 entries.

- `NPCID.NegativeIDCount` is a sentinel, not an NPC. The extractor already skipped `Count`;
  it now also skips `*Count` and the `None`/`None2`/`None3` placeholders for unoccupied ids.
  `data/npcs.json` goes 763 → 759, and nothing else changed in the regenerated file.
- The other seven were **real templates the scan was throwing away**. The Moss Hornet variants
  sit next to seven default-state NPC objects carrying netID 0, which made their run 14 objects
  for 8 distinct keys. The old rule scored a run as a whole and discarded it if it was not near
  enough to one-to-one, so all seven died with it. The rule now judges **keys**: from each run,
  keep those appearing exactly once. Strictly more robust, and every existing scan test still
  passes unchanged.

The `NPC` fallback kind is now empty, which is the invariant worth remembering: anything in it
is a bug report.

## Phase 3 — Tests

- **290 passed** headless, up from 269 at v0.25.0.
- `tests/test_npc_content.py` (8): one template per netID; the negative variant netIDs survive
  (ContentSamples is keyed on netID and those are exactly the entries `npcs.json` names);
  absurd netIDs rejected; a horde of same-type live NPCs is not mistaken for the table; the
  real table wins over a smaller one-to-one run; the NPC vtable is the one the array elements
  agree on, and a same-length array whose elements disagree is rejected; **and the Moss Hornet
  regression** — unique keys must survive duplicated neighbours.
- `tests/test_npc_spawn.py` (6): a non-boss spawns immediately with no countdown; a boss
  declined at the confirmation never spawns; a confirmed boss counts all the way down first;
  cancelling mid-countdown spawns nothing; a second boss request replaces the first countdown
  rather than leaving two running behind one Cancel button; the Spawn button is offered for
  NPCs only and reads "Spawn boss…" for a boss.
- `tests/test_compendium_tab.py` (+2): Give is offered for items and withheld from NPCs — which
  must not key on the kind string now that NPCs report Boss/Monster/… — and the kind dropdown
  widens for kinds added after it is first shown.
- **Three mutation checks**, because these tests exist to catch specific bugs: removing the
  boss gate fails 4 tests; restoring the whole-run scan rule fails the Hornet test; removing
  the dropdown's size policy fails the dropdown test.
- Every NPC offset was verified against vanilla stats obtained independently of this project:
  Blue Slime 25/7/2, Zombie 45/14/6, Demon Eye 60/18/2, Eye of Cthulhu 2800/15/12, King Slime
  2000/40/10, Moon Lord 45000 life, critters 5 life / 0 damage. `NPC.active` was confirmed two
  ways: clear in all 647 templates, and set on exactly the live `Main.npc` slots — the sole
  exception being a despawned Squirrel that had left its type behind.
- **Live, maintainer-verified**: spawning works from the tab. Two Bunnies and a Zombie were
  also placed via the CLI into slots 12, 29 and 30 with correct netID, type, life, size and
  `whoAmI`, and the game stayed up throughout.

## Phase 4 — Code quality

- The template scan was generalised rather than duplicated: `_scan_objects` and
  `_template_table` now serve both items and NPCs, and `find_item_templates` is three lines.
- `Service._template_cache(kind, scan)` likewise backs both caches; a test pins that items and
  NPCs cache to different files and that a second read does not rescan.
- The item/NPC distinction moved from `kind == "NPC"` to an explicit `npc` flag on the entry.
  Keying UI behaviour on a display string broke the moment real kinds arrived — Give would have
  been offered for every monster in the game. Caught before shipping and covered by a test.
- `Main.npc` is found by a pinned build constant *validated on use* (length must be
  `maxNPCs + 1`, elements must agree on a vtable), falling back to scanning Main's statics.
- flake8 clean at the project's ~100-col convention on all changed code. The same three
  pre-existing hits remain in untouched lines.

## Phase 5 — Security review

- No `eval`/`exec`, no `pickle`, no shell, no new network calls, no new dependencies.
  `pip-audit 2.10.0`: *No known vulnerabilities found*.
- **The new memory writes are the thing to review**, and they are bounded: six writes, all at
  `slot_object + constant`, into an NPC object the game itself allocated and had marked
  inactive. Sizes are fixed (two spans totalling 552 bytes, then 4/8/8/16/1 bytes). Nothing is
  computed from user input except the distance, which only moves a float, and the resulting
  x is clamped away from tile 0 so it cannot land outside the map.
- No new patches, no code caves, no JIT modification — phase 2 adds nothing to the build ledger
  because it changes no game code.
- The privileged surface grew by one op (`spawn-npc`), added to the `SERVE_OPS` allowlist with
  explicit argv, like every other op.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. Nothing patched, nothing persisted, no save-format change. A
  spawned NPC is as permanent as any other NPC the game spawns.
- **Data regeneration is reproducible**: `data/npcs.json` was regenerated from the game's own
  exe and diffed — only the 4 sentinels were dropped, no name changed.
- **Caches are versioned by build** and regenerate in ~2s if deleted.

## Known limitations

- **The boss gate is NOT verified in-game.** It is built and unit-tested in both directions,
  but summoning a boss needs nightfall. The criterion is recorded unchecked, and the risk is
  real rather than theoretical: a template copy is not `SetDefaults` + `NewNPC`, so a boss that
  reads a static those set (`NPC.plantBoss`, `golemBoss`) may behave oddly.
- **`ai[]` is not reset.** A spawned NPC starts with whatever the slot's previous occupant left
  there. Zeroing it was considered and rejected: the two length-4 float arrays could not be
  identified as `ai` with confidence, and clearing the wrong one is worse than a stale value
  the game's state machine overwrites.
- **Slot selection is not atomic** — read then write, so the game's spawner could claim the
  same slot in between. Microsecond window, loser is simply overwritten, accepted.
- **Multiplayer is out of scope**: nothing syncs the spawn to a server.
- **Still open from Phase 1**: the Wiki and Give buttons have not been clicked in a running
  session.
- **Spec 034** still has its one open criterion (`SmartCursorLookup` before it is JIT-compiled).

## Result

Gates pass. Approved for commit and tag `v0.26.0`, with the boss gate recorded as built but
unverified in-game.
