# Validation Report — terrariabonker v0.22.0

**Date**: 2026-08-23
**Scope**: Spec 032 — make the vanity accessory slots functional.

## Summary

The ask was "more accessories". Recon found that Terraria already draws seven more accessory
slots than it uses: `UpdateVisibleAccessories` runs `ApplyEquipVanity` for slots `13..19`
(which is why an info accessory like a Depth Meter has always worked in the vanity column),
but `UpdateEquips` only ever calls `ApplyEquipFunctional` for `3..9`, so wings, boots,
defense and damage do nothing there.

Widening the two `UpdateEquips` loop bounds from 10 to 20 makes the vanity column fully
functional — no new slots, no UI change, no save-format change. The hazard is that
`ApplyEquipFunctional` indexes `hideVisibleAccessory[slot]`, and that array is `bool[10]`, so
a slot of 13..19 throws every frame; a three-instruction cave clamps the slot to its
functional mirror. PASS 2 found the slot already in `eax` at the store, so the clamp needs
nothing from the stack frame.

## Phase 3 — Tests

- **201 passed** headless, up from 193.
- `tests/test_vanity_accs.py` (8): both bounds widen and revert; the call site takes a
  `jmp`; the stub is `cmp/jl/sub` + the displaced stores + `jmp back`; every vanity slot maps
  into the hide array; the cave is scrubbed on disable; `is_enabled` tracks the toggle; and a
  cold re-resolve still matches **with the cheat applied** — the trap that would otherwise
  leave the cheat impossible to turn off after a restart.
- `tests/test_build_ledger.py`: a later-derived anchor claims only the build it was confirmed
  on and does not inherit the default verification set.
- **Live, maintainer-verified** on a real world with the entire vanity accessory column
  occupied and the functional column empty:
  - Fledgling Wings, Shield of Cthulhu, Shiny Red Balloon and Hermes Boots all took effect.
  - The **Warding** prefixes on those accessories contributed their defense — the second
    edit (`equip_benefits` → `GrantPrefixBenefits`) working.
  - Real vanity **armour** in slots `10..12` stayed inert: no defense change, no set bonus.
  - Depth Meter and Tungsten Watch, which already worked in that column, were unchanged.
  - No exception spam, no crash, with all seven slots exercised.

## Phase 4 — Code quality

- The clamp fits the existing `Injection` model exactly (`make_body` = clamp, `overwrite` =
  the displaced stores, `rerun_overwrite` replays them), so no new cave machinery was
  written. The spec had assumed this would need `Cheat` to grow multiple edits; PASS 2 showed
  `Injection` was the right home, and the spec records that correction.
- A shared `Edit` type carries the two loop-bound changes so they toggle together, applied at
  every site their anchor resolves to (spec 030's multi-site rule).
- Both anchors wildcard exactly what the cheat writes — the seven displaced bytes and the two
  bound immediates — so a cold re-resolve works while the cheat is on. This is the failure
  mode `reset_block` and `place` already document, and it is covered by a test.
- flake8 clean at the project's ~100-col convention on changed files.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no new dependencies (`pip-audit 2.10.0`: *No known
  vulnerabilities found*).
- The injected bytes are fixed constants (`83 F8 0A 7C 03 83 E8 0A`) with no user input; the
  cheat takes no tunable value.
- Writes are confined to resolved anchor sites and borrowed int3 caves through the existing,
  already-reviewed machinery. Disable restores the original bytes and scrubs the stub.
- The clamp is itself the safety property: it keeps an array index in bounds that the widened
  loop would otherwise push past the end.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`; the cheat is off by default and disabling restores the original
  bytes at every site. A game restart clears it like every other code patch.
- **No save-format change.** The vanity slots already hold these items; the cheat only
  changes whether the game reads them. A world played with it on is unaffected once it is off.
- **Ledger**: both anchors are recorded as verified on `1.4.5.7+24893155` only — they were
  derived on that build and never existed on the original one, so they do not inherit the
  default verification set.

## Known limitations

- **Duplicate accessories stack.** The same accessory in a functional and a vanity slot
  applies twice; vanilla's UI only dedupes within the functional column. Intended for a
  trainer, but it is a behaviour change.
- **Hide-visual coupling.** A vanity accessory follows the hide-visual flag of its functional
  mirror (slot 13 reads `hideVisibleAccessory[3]`), a consequence of the clamp.
- **Accessories from inventory/bank slots** — the other shape of the original request —
  remains unimplemented; it needs the item source redirected inside the cave and a per-frame
  cost measurement.

## Result

All gates pass. Approved for commit and tag `v0.22.0`.
