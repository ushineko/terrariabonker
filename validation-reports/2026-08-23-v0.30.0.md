# Validation Report — terrariabonker v0.30.0

**Date**: 2026-08-23
**Scope**: Spec 038 — restore item edits by what the item is, not where it sat.

## Summary

Auto-restore warned about seven item edits it could not re-apply. All seven were noise. The
profile now records only what needs restoring, and finds the item by type rather than slot.

## The part worth reading

The reported message was:

```
[auto-restore] 7 saved item edit(s) not re-applied — slot(s) 31, 32, 33, 34, 35, 36, 46
no longer hold the item they were saved for (Tungsten Watch, Shield of Cthulhu, ...)
```

**Three faults, only one of them the one the message describes.**

*It recorded defaults as edits.* The edit dialog is pre-filled with the item's current
values and submits all of them, so `cmd_set_item` stored every field. A saved accessory read
`{"damage": -1, "use_time": 100, "pick": 0, ..., "prefix": 65}` — everything but the prefix
is the Tungsten Watch's own default.

*It recorded what the game already persists.* Auto-restore exists because Terraria saves
type + stack + prefix and regenerates the rest. The code's own comment said exactly that,
and then saved all three anyway. Six of the seven "failures" were accessories whose only
change was a prefix, which had survived on its own.

*Slot is the wrong key* — the real fault. An edited item that moves loses its edit silently,
and moving accessories into the equipment column is precisely what specs 032 and 033
encourage.

The fix: record only the regenerated fields, only where they differ from the item's own
default (compared against the ContentSamples template the compendium already caches), and
match by type at restore, applying to every copy. An item not in the inventory is reported
as *waiting*, not as a failure.

**Measured on the real profile that produced the warning: 11 entries became 1.** Every
pruning decision was checked against the game's own templates:

| item | verdict |
| --- | --- |
| Book of Skulls | damage **45** vs default 29, use time **12** vs 32 — kept |
| Slime Whip, Boomstick, Wood, and the six accessories | every field was the item's default — pruned |

The one real edit survived; the warning cannot recur because the entries behind it no
longer exist.

## Phase 3 — Tests

- **354 passed** headless, up from 347.
- `tests/test_profile.py` (6): only regenerated fields kept; an edit with nothing
  restorable is not stored; a slot-keyed profile migrates — the fixture is the real one
  from the report.
- `tests/test_service.py` (5 rewritten): an edited item is found wherever it now sits;
  every copy is restored; an absent item is `absent` rather than skipped **and its edit is
  kept**; an all-defaults edit is forgotten; a real edit survives pruning.
- `tests/test_build_ledger.py` (3 rewritten): the absent-item line is asserted by
  *forbidding* the old alarming phrases ("no longer hold", "overwritten", "not
  re-applied", "failed") and by forbidding the word "slot" — slots are no longer identity.
- **Mutation check**: pinning the match back to slot 0 fails both identity tests.

## Phase 4 — Code quality

- The template comparison reuses the compendium's per-build cache rather than scanning per
  item. The cache self-heals: one written before this change lacks `use_anim`,
  `auto_reuse` and `tile_boost`, and is rescanned rather than trusted.
- No baseline (cache unreadable) means *record the field*, so a missing cache degrades to
  the old behaviour rather than to silently forgetting edits.
- Empty-slot markers stay keyed by slot, because clearing slot 12 is a statement about the
  slot rather than about an item.
- flake8 clean on changed files; the same pre-existing hits remain in untouched lines.

## Phase 5 — Security review

- No `eval`/`exec`, no shell, no network, no new dependencies. `pip-audit 2.10.0`: *No
  known vulnerabilities found*.
- No new memory writes: the same `set_item` path, driven by fewer fields than before.
- The profile is the user's own config file, written atomically under a lock as before.

## Phase 5.5 — Release safety

- **Rollback**: `git revert`. The profile is disposable and rebuilds as edits are made.
- **Migration is one-way**: a rewritten profile no longer carries stack/prefix. They were
  never restorable, so nothing is lost in practice. The pre-migration file was kept aside
  during verification.

## Known limitations

- **Type-keyed edits cannot distinguish two copies.** Two Zeniths cannot hold different
  saved damage. Slot-keying already lost the edit the moment the item moved, which is worse.
- **Stack is deliberately not restored.** The game saves it.
- **An absent item's edit is kept indefinitely.** Chosen over self-cleaning, which could
  silently forget an edit for something deliberately stashed.

## Result

Gates pass. Approved for commit and tag `v0.30.0`. Spec 038 COMPLETE.
