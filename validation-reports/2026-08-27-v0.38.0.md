# Validation Report — terrariabonker v0.38.0

**Date**: 2026-08-27
**Scope**: A mid-project technical review, the three live bugs it found, its eight
remediation items, and the first half of the method-level refactor it prompted (spec 045).

## Summary

No new cheats. This release is the project auditing itself: a three-pass review of 11,433
lines of source and 7,440 of tests, then the work it produced — three bugs fixed, six
structural findings addressed, two new modules, and 38 new tests.

The interesting part is not the refactoring. It is that **the review and the fixes each
found things the 546-test suite could not see**, and that four separate fixes needed a
second or third attempt because the first test passed against the bug it was written to
catch. That pattern is why the review's policy candidates were lifted into `AGENTS.md`
rather than left as a document nobody reads twice.

## The part worth reading

**Three live bugs, none of which had a test.** All 546 tests passed before the fixes and
after them, which is the whole finding.

- `_inventory_visible` compared `currentIndex()` to `indexOf(widget(1))` — which is `1` by
  definition, the **Effects** tab. Inventory is tab 3, so the 1 Hz grid sync ran only while
  Effects was showing and never while the user was looking at the grid it exists to refresh.
  The same file warns against this exact mistake eight hundred lines earlier; the sibling
  handler had been fixed and this one had not.
- `fast_mining` and `long_reach` returned whichever inventory copy came last — usually an
  inert load-time snapshot — and the CLI prints that count to the user. The writes were
  fine; the report was a lie about what changed.
- `version.guard` had `"[version] WARNING" if force else "[version] WARNING"`. Removed
  rather than implemented: the `--force` case is already called out on the next line.

**One offset, five spellings.** The mono szarray shape (`+0x0C` length, `+0x10` data) was
declared independently in four modules under four names, plus a bare `0x10` inline in
`locate`. `Main`'s static offsets were spread across five modules despite all being offsets
into the same block. A game update is the routine event this project is built around, and
re-deriving one number started with finding every spelling of it. They now live in
`layout.py`; the module-local names stay, because imports depend on them, and only the
values moved.

**A test that had quietly stopped covering new code.** `client.COMMANDS` was a hand-written
set of subcommand names and had gone stale by seven — `catch-tick`, `catch-stop`,
`fishing-buffs`, `build-check`, `accept-build`, `restore`, `extract-sprites` — so
`test_view_parity` silently guarded none of two releases' worth of argv builders while
still reading like coverage. It is derived from the samples now, and a new test fails if any
`*_argv` builder has no sample. 40 samples cover all 28 builders.

**Four fixes needed more than one attempt**, each time because the first test passed against
the bug:

| Attempt that failed | Why |
|---|---|
| `long_reach` regression | The fixture's two inventory copies differed only in pickaxe-ness, which `long_reach` never reads |
| Layout identity check | `0x10 is layout.ARR_DATA_OFF` is `True` — CPython interns small ints, so a re-declared constant sailed through |
| Parity assertion | Derived the expected command from `argv[0]`, i.e. proved `argv[0]` equals itself |
| `replies()` dict guard | Unreachable: only lines starting with `{` are parsed, and those always decode to objects. Deleted rather than tested |

Every one was caught by reverting the fix and watching the new test fail — not by writing
the test and trusting it.

**A behaviour change the suite could not see.** Splitting `catch_tick` moved a `break` out
of the recast guard, turning "not ready to cast yet" into "stop looking for a bite" — so a
bite arriving mid-tick would be dropped. All 579 tests passed. It was caught by reading the
diff. `_ready_to_recast` is a separate predicate for that reason, and a test now fails if it
is collapsed back.

**A reviewer finding rejected on inspection.** The review called four things in `patcher.py`
dead. `Anchor.unique`, `Anchor.variants` and `_ALSO_VERIFIED` are exercised by
`test_build_ledger` and are how a game update would be absorbed — deleting them would have
removed tested capability on a reviewer's say-so. Only the cave path was genuinely
uncovered, and it got a test that drives it rather than a delete.

## Tests

584 pass (`pytest`, headless, against the synthetic memory image — no game, no root). Up
from 546 at v0.37.0.

Eight mutations run against this release's changes, all caught:

| Mutation | Outcome |
|---|---|
| the vein search digs past the ground it lands on | caught |
| the extractor's queue is left armed after a dig | caught |
| "not ready to cast" becomes "stop looking for a bite" | caught |
| the arena springboard is left hooked | caught |
| the springboard cave is left unscrubbed | caught |
| the grid sync watches the wrong tab | caught |
| a module re-declares a shared offset | caught |
| `error_in` stops detecting worker errors | caught |

Earlier passes in this cycle also produced two **equivalent** mutants, recorded as such
rather than counted as passes: `find_bobbers`'s `active` check (redundant, `read_bobber`
re-checks) and reading the buff clock after `renew` rather than before (identical
classification, because `renew` never shortens). Both were findings about the code, and one
produced a comment correction.

## Refactoring (spec 045)

Behaviour-preserving, with the tests as the contract — **no test changed** across the three
splits:

| Method | Before | After |
|---|---|---|
| `extract_vein` | 107 lines, 7 jobs | 41 + `_vein_regrowth` 32 + `_drain_vein` 45 |
| `catch_tick` | 79 lines, 3 nested deadline loops | 47 + four helpers, 11–23 each |
| `arena` | 73 lines | 39 + `_bootstrap_arena` 47 |

Characterization tests went in **first** on each: eleven of them, pinning the stop-at-ground
walk, the disarm-in-`finally`, the arena unhook and cave scrub, the paused-game diagnostic,
and `on_wait` firing once. The arena bootstrap had no coverage at all beforehand — every
existing test stubbed `arena()` wholesale — despite being the code that hangs a jump on live
game code.

Per-cheat arena protocol also moved off `Patcher` into `arena_state.py`: eight methods for
two cheats had accumulated on the generic patch engine, so a third cheat's arena words would
have landed there too.

Tiers 2 and 3 of spec 045 are deliberately unstarted. `Service` and `MainWindow` remain god
classes; splitting them is a boundary-design decision and wants its own spec.

## Security review (Phase 5)

- No `eval`/`exec`, no `subprocess`, no sockets, no network calls in shipped code.
- No hardcoded credentials.
- Dependencies unchanged since v0.34.0, so `pip-audit` was not re-run.
- No new writes to the game. The refactors move existing writes between methods; the
  mutation table above is the evidence that the ordering guarantees survived — the
  disarm-in-`finally`, the springboard unhook, and the cave scrub.
- `client.error_in()` centralises what was `"[ERROR]" in out` substring matching at four
  call sites, one of them written against a `{"error": ...}` reply the worker never sends.

## Release safety

- **Rollback**: `git revert` or the previous tag. No new patches, no save-format change, no
  state-file change. The arena stamp is unchanged from v0.37.0 (`TBARENA2`), so a running
  arena from that version is still adopted.
- The one user-visible behaviour change is the grid sync now running on the right tab, which
  is a fix; the two report-value fixes change numbers the CLI prints, not what it writes.

## Known gaps

Unchanged from v0.37.0, and none of them shipped-behaviour risks:

- **`RELEASE_ITEM_OFF` (`Player+0x67F`) is still not identified.** Auto-use writes it and
  casting works without it; it is a byte with the right shape and nothing more.
- **The auto-use hook's call target is identified by shape and position**, not by mono
  metadata.
- **Whether switching items destroys an outstanding bobber was never settled.**

New with this release:

- **`service.py` has 59 deferred imports** against 10 top-level. The rule is now written
  down in `AGENTS.md` for new code; the existing 59 were not cleaned up.
- **`Service` (~1310 lines) and `MainWindow` (~1560) are still god classes**, with five
  parallel `_inflight` flags and five watch/tick/stop triples between them. Recorded in the
  review §2.1 and deferred by spec 045.
- **Two tier-3 methods** (`spawn_npc`, `_patches_group`) were assessed and left alone; the
  decision is recorded in spec 045 rather than silently skipped.
